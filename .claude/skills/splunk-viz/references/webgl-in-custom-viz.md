# カスタム viz で WebGL を使う（実機検証結果と実装ナレッジ）

`/splunk-viz` スキルの参照ナレッジ。**Splunk Dashboard Studio 拡張 viz の iframe 内で
WebGL が使えるか**を実機検証した結果と、シェーダで質感を作るときの実装知見をまとめる。

検証日: **2026-08-02**（`webgl-probe` という使い捨ての検証 viz を作って実施。
本ナレッジに結果を移した後、プローブ本体は削除済み）。
成果物: `visualizations/liquid-tube/`（この検証を土台に作った本番 viz）。

---

## 1. 結論（実機確認済み）

> **Splunk のカスタム viz（Studio 拡張）の iframe 内で WebGL2 が使える。**
> フラグメントシェーダで屈折・透過・反射を伴う質感表現ができる。

検証環境と実測値:

| 項目 | 値 |
|---|---|
| Splunk | 10.4.1 |
| ブラウザ | Chrome（ANGLE 経由 / Direct3D11 バックエンド） |
| API | **`webgl2` が取得できる**（`webgl` へのフォールバック不要） |
| GPU | ANGLE (NVIDIA GeForce RTX 5080, Direct3D11 vs_5_0 ps_5_0) |
| MAX_TEXTURE_SIZE | 16384 |
| GLSL | **GLSL ES 3.00（`#version 300 es`）がそのまま通る** |
| シェーダ | コンパイル・リンクとも成功 |
| 描画 | `readPixels` で実際に色が出ることを確認（rgb=37,233,85） |
| フレームレート | **62fps**（SDF + フレネル + Beer-Lambert + 気泡22個の全画面シェーダ） |
| コンテキストロスト | 発生せず |

**この結果は上記1環境でのもの。** 他のGPU・ブラウザ・Splunk版での動作は未確認。
WebGL2 が取れない環境もありうるので、**取得失敗時のフォールバック表示は必ず入れる**。

### 未検証のまま残っている項目

正直に記録しておく（`webgl-probe` の ROUND 3/4 は実施しないまま本番へ移行した）:

- **複数パネルを同時に置いたときのコンテキストロスト**（ブラウザの同時 WebGL
  コンテキスト数上限は実装依存で 8〜16 程度。超えると古いものが失われる）。
  → liquid-tube は **1 viz = 1 コンテキスト**なので、パネルを何枚も並べると
  この上限に当たる可能性がある（**未検証**）。
- テーマ切替・パネルのリサイズ・編集⇄表示モードの往復での復帰（**未検証**）。
  ただし liquid-tube は ResizeObserver で canvas を作り直す実装になっており、
  ローカル検証では壊れていない。

## 2. 実装の要点

### コンテキスト取得（背景を透過するなら `alpha: true` 必須）

```js
const gl = canvas.getContext('webgl2', {
    antialias: true,
    alpha: true,              // ← false だと canvas が不透明になり背景を透かせない
    premultipliedAlpha: true,
});
if (!gl) { /* フォールバック表示。落とさない */ }
```

**背景を透過させるには3点セットが必要**（1つでも欠けると透けない）:

1. コンテキストを `alpha: true` / `premultipliedAlpha: true` で取得
2. シェーダが **premultiplied alpha** で出力する … `outColor = vec4(col * alpha, alpha)`
3. **viz コンテナの CSS 背景も `transparent`** … ここを塗ると canvas の透過が無意味になる

ブレンドも premultiplied に合わせる:

```js
gl.enable(gl.BLEND);
gl.blendFunc(gl.ONE, gl.ONE_MINUS_SRC_ALPHA);
gl.clearColor(0, 0, 0, 0);
```

> **iframe の外にある背景は読めないが、透かすことはできる。**
> シェーダから背景色を取得する手段は無い。しかし **alpha を下げればブラウザが合成する**ので、
> 「背景を再現する」必要は無い。**合成はブラウザの仕事**と割り切るのが正解。

### 全画面クアッドは「大三角形」1枚で足りる

```js
gl.bufferData(gl.ARRAY_BUFFER, new Float32Array([-1, -1, 3, -1, -1, 3]), gl.STATIC_DRAW);
gl.drawArrays(gl.TRIANGLES, 0, 3);
```

### rAF ループは張り直さない（stale closure 回避）

オプションやデータが変わるたびにコンテキストを作り直すと重いうえにチラつく。
**ループは `size` の変化時だけ張り直し、値は ref 経由で読む**（world-map 等と同じ規約）:

```js
const stateRef = useRef({ tube, opts });
stateRef.current = { tube, opts };          // 毎レンダー代入
// ...
const frame = (now) => {
    const st = stateRef.current;             // ← 最新値をここで読む
    gl.uniform1f(uLevel, st.tube.value);
    rafRef.current = requestAnimationFrame(frame);
};
```

### GLSL のループ上限は定数（オプションで可変にする方法）

GLSL のループ回数はコンパイル時定数でなければならない。
**上限を定数にして `break` で抜ける**形にすれば、オプションで可変にできる:

```glsl
for (int i = 0; i < ${MAX_BUBBLES}; i++) {   // MAX_BUBBLES は JS 側のテンプレートで埋める
    if (i >= nb) break;                       // nb は uniform（可変）
    ...
}
```

### WebGL1 へのフォールバックを書くときの注意（未検証）

実機は webgl2 だったのでこの経路は通っていないが、書くなら:

- `#version 300 es` を外し、`in/out` → `attribute/varying`、`outColor` → `gl_FragColor`
- **`fwidth` は GLSL ES 1.00 では標準に無い**（`OES_standard_derivatives` 拡張が必要）。
  拡張の有無は環境依存なので、固定値（例 `1.5 / uRes.y`）に置き換えるのが安全

## 3. 質感を作るシェーダの定石（liquid-tube で実装）

「リアルな見た目」は**光の振る舞いを式にする**と出る。SVG/CSS では以下が原理的に書けない。

| 現象 | 式 | 効果 |
|---|---|---|
| 透明体の吸収 | **Beer-Lambert** `T = exp(-σ · 光路長)` | 深い/厚いほど濃くなる |
| 縁が光る | **フレネル** `pow(1 - dot(N,V), n)` | ガラスらしさの中核 |
| 形状定義 | **SDF**（符号付き距離関数） | 解析的な形。AA も `fwidth` で綺麗に出る |
| 屈折 | 参照 uv をずらす（screen-space 近似） | レイトレース不要で「歪み」が出る |
| 質感の揺らぎ | 値ノイズ `vnoise` の補間 | 乱数のままだとチラつく。**必ず補間する** |

### やらかした間違い（すべて実測で発見・修正済み）

**同じ轍を踏まないよう、原因と症状をセットで残す。**

| 症状 | 原因 | 教訓 |
|---|---|---|
| 液体が**不透明**で何も透けない | `col = liquidCol * ...` と **代入**していた。Beer-Lambert は「背景に透過率を**掛ける**」法則 | 「透過を計算した」と「透過させた」は別。**掛けているか**を確認する |
| 赤い液体が**オリーブ色**になる | 散乱項を `liquidCol * (1 - T)` にしていた。σ は「補色ほど大きい」ので**主要チャンネルほど T が大きく**なり、`(1-T)` を掛けると**主要チャンネルが最も弱くなる**（色相反転） | 散乱は**スカラーの密度**に比例させる。色相を歪める式になっていないか数値で確かめる |
| 管の内側が**黒く沈む** | 透かす先を暗色でハードコードし、`alpha = 1.0` で塗り潰していた | 透明体に `alpha = 1.0` を決め打ちしない。**部位ごとに物理的な不透明度**を与える |
| 気泡が**シールのよう** | `length()` の真円＋均一リング | 気泡は**上昇で扁平**になり、リングは**光源側に偏る**。個体差と時間変化を入れる |
| **底の輪郭が点線状**になる | AA を `col *= smoothstep(...)` と**黒に向かって**フェードしていた | `mix(背景色, 管の色, cover)` で**背景へ溶かす** |
| 丸底の陰影が**急に切り替わる** | 法線を `uv.x` だけから作っていた（丸底では破綻） | **SDF の距離**から「縁への近さ」を測る。直管でも丸底でも一貫する |
| 管が**画面からはみ出す** | uTop/uBottom を**クリップ座標(-1..1)**で渡した。シェーダの uv 空間は**縦 -0.5..0.5** | **単位を明示**する。uniform のコメントに座標系を書く |
| パネルを大きくするほど**下が見切れる** | 試験管は**上下非対称**（上は平ら/下は丸底 R が出る）＋肉厚 WALL。なのに「中心から上下対称」として逆算していた（外形が **1.21倍**に膨張） | **形状の非対称性を式に反映**する。比率で膨らむ誤りは**サイズを変えると悪化**する |

## 4. ローカル検証のやり方（WebGL は happy-dom に無い）

`yarn verify`（happy-dom）では WebGL が動かない。**`getContext('webgl2')` をスタブ化して
「uniform に何が渡ったか」を検証する**方式にすると、実機なしでもかなり守れる。

```js
win.HTMLCanvasElement.prototype.getContext = function (type, attrs) {
    if (type === 'webgl2') { gpu.contextAttrs = attrs; return makeGLStub(); }
    return null;
};
// makeGLStub() は uniform1f/uniform3f 等を記録するだけの偽 gl オブジェクト
```

これで検証できること（liquid-tube では 87 件）:

- 値 → 液面の高さの変換、しきい値の**境界値**（下限以上・上限未満）
- **透過フラグ**（`alpha:true` / premultiplied / clearColor / blendFunc）
- テーマごとの背景色、DOS 文字列のパース、堅牢性（空データ・不正値）

### ⚠ 「JS が渡す値」だけ見るテストは**シェーダのバグを見逃す**

liquid-tube で実際に起きた。**JS 側は正しく、シェーダの形状計算が誤っていた**ため
全テストがパスしたまま「下が見切れる」不具合が残った。

対策: **シェーダの寸法計算を JS で再現するテスト**を書く。

```js
// シェーダと同じ式を JS で再現し、外形が指定範囲に一致するか検証する
const shaderBounds = (uTop, uBottom, resW, resH, tubeW) => { /* main() と同じ式 */ };
// 複数のパネル寸法で誤差 < 1e-6 を確認（比率の誤りはサイズを変えると露見する）
```

**複数の縦横比で回すこと。** 比率を間違えている不具合は、1つのサイズだけでは
偶然一致して見えることがある（実際 300px では +27px、1200px では +97px と差が開いた）。

## 5. パフォーマンス（実測）

- 全画面フラグメントシェーダ（SDF + フレネル + Beer-Lambert + 気泡22個の
  ノイズ変形・回転・スペキュラ）で **62fps**
- `animSpeed = 0` にすると rAF は回り続けるが時間が進まないため静止する
  （完全に止めたい場合は rAF 自体を止める実装にする余地がある）
- **重くなりやすいのは気泡ループ**。1個あたり `vnoise`×2・`atan`×1・`sin`×4 程度。
  数を増やすときは実機で fps を確認する

## 6. 使うかどうかの判断

**WebGL を使うべき場合**:
- 屈折・透過・反射といった**光学的な質感**が要件（SVG では原理的に出せない）
- 全画面を毎フレーム塗り替える表現

**使うべきでない場合**:
- 図形・線・文字が主体 → **SVG のほうが軽く、テキスト検索・アクセシビリティでも有利**
- 依存追加を避けたい場合でも WebGL 自体は**ブラウザ内蔵なので依存は増えない**
  （liquid-tube は three.js 等を使わず**生の WebGL** で書いており、依存追加ゼロ）
