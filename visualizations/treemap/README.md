# Treemap

![表示例](examples/example.png)

Splunk **Dashboard Studio** 向けのカスタムビジュアライゼーション（React/JSX）。

階層構造を「**面積**」で表すツリーマップです。`index > sourcetype > host` のような入れ子を
一画面に収め、**どこが容量・件数を食っているか**を一目で示します。

ディスク使用量・ライセンス消費・アラート内訳など、「全体に対する構成比を、階層をたどりながら
把握したい」場面に向いています。

---

## 特徴

- **squarified レイアウト**（Bruls, Huizing, van Wijk 2000）— 単純な slice-and-dice だと
  細長い短冊が生まれて面積の比較が破綻するため、各タイルの縦横比が 1 に近づくよう行を積む方式を実装。
  実測で最悪アスペクト比 6 未満・中央値 3 未満に収まります。
- **クリックで掘り下げ** — グループタイルをクリックするとその枝を根として展開。
  パンくずリストで任意の階層へ戻れます。掘り下げ位置は `drillPath` オプションに保存され、
  編集→保存でダッシュボードに永続化できます。
- **階層は 1〜3 レベル** — サーチが返すラベル列の数に応じて自動で組み立てます。
  同時に表示する階層数（`maxDepth`）は編集画面で切り替え可能。
- **色は第1階層で決まり、子は濃淡で表現** — 掘り下げても枝の色が変わらないので、
  どのグループを見ているかを見失いません。パレットは色覚特性（第2色覚）に配慮した8色。
- **ホバーでツールチップ** — カーソルを乗せると、階層のパス・値・全体比・内訳件数を
  カード表示。掘り下げ可能なタイルには枠が付き「クリックで掘り下げ」と示します。
  ツールチップはパネルの端で自動的に反対側へ折り返すので、見切れません。
- **見切れにくいラベル** — 入らなければ即あきらめるのではなく、
  **フォントを縮める → 値を落とす → 名前を … で詰める** の順に段階退避します。
  グループ見出しも「名前＋値」が入らなければ値を捨てて名前を優先します。
- **タイル数の上限** — 超過分は「その他（N件）」に集約して、極小タイルの洪水を防ぎます。
- **負の値は除外** — 面積では負を表現できないため、落としたうえで件数を注記に出します
  （黙って消さない）。
- **オートフィット** — `ResizeObserver` でコンテナ実寸を測り、領域いっぱいに描画。
- ライト／ダーク両テーマ対応、完全オフライン（外部通信なし）。

## データ仕様

| 役割 | 必須 | 説明 |
| --- | --- | --- |
| 第1階層 | **必須** | 最上位のグループ（index / department など）。 |
| 第2階層 | 任意 | 第1階層の内訳。 |
| 第3階層 | 任意 | さらにその内訳（`maxDepth` を 3 にすると同時表示）。 |
| 値（面積） | **必須** | 正の数値。同じ組み合わせの行は合算されます。 |

### 列の自動判定

編集画面でフィールドを選択しなかった場合、以下の順で自動判定します（明示選択が常に優先）。

- **値（面積）** … 一番右の数値列（`stats` の集計列は末尾に来るため。`_` 始まりは除外）
- **階層** … 値列以外の非数値列を左から順に最大3つ

`| stats count by index, sourcetype` のような素直な出力なら、そのまま何も設定せずに描画されます。

## サンプル SPL

### 1. 2階層（推奨・最も使う形）

```spl
| makeresults format=csv data="index,sourcetype,count
web,access_combined,4820
web,error_log,1240
web,ssl_access,860
db,mysql_slow,2100
db,mysql_error,540
db,mysql_general,310
security,auth,1680
security,firewall,3200
security,ids_alert,420
app,json_app,1950
app,app_error,280"
| eval count=tonumber(count)
| table index sourcetype count
```

### 2. 3階層（`maxDepth` を 3 にすると host まで一度に表示）

```spl
| makeresults format=csv data="index,sourcetype,host,bytes
web,access,web-01,52000000
web,access,web-02,38000000
web,error,web-01,4100000
db,query,db-01,91000000
db,query,db-02,27000000
db,slow,db-01,6400000
security,auth,auth-01,15000000"
| eval bytes=tonumber(bytes)
| table index sourcetype host bytes
```

### 3. 実データでの典型パターン

インデックスごとのイベント件数の内訳:

```spl
index=* | stats count by index, sourcetype
```

ライセンス消費（インデックス別・ソース別のデータ量）:

```spl
index=_internal source=*license_usage.log type=Usage
| stats sum(b) as bytes by idx, st
| rename idx as index, st as sourcetype
```

ディスク使用量の内訳:

```spl
| rest /services/data/indexes
| stats sum(currentDBSizeMB) as sizeMB by datatype, title
```

## 編集画面のオプション

| セクション | 項目 | 説明 |
| --- | --- | --- |
| データフィールド | 値（面積）／第1〜第3階層 | 各フィールドの明示選択（未設定は自動判定） |
| 配色 | 色1〜8／子タイルの濃淡 | 第1階層の並び順に色を割り当て。9件目以降は繰り返し |
| 階層とタイル | 同時表示の階層数／タイル最大数／間隔／角丸 | 階層数は 1〜3。上限超過分は「その他」に集約 |
| 表示 | タイル名／値／割合／グループ見出し／パンくず／凡例／掘り下げ／アニメーション | |
| 数値 | 小数点以下の桁数／省略表記 | 既定は省略表記オン（1.5M など） |
| デバッグ | オプションのデバッグ表示 | 解決した列・掘り下げ位置・合計値をダンプ |

## 開発コマンド

```bash
yarn install
yarn build        # dist/custom_viz_treemap/visualization.js を生成（esbuild）
yarn verify       # happy-dom によるローカル検証（Splunk 実機不要）
yarn package      # dist/*.spl を生成
```

## デプロイ（アンインストール・再起動なし）

1. `npm version <patch|minor> --no-git-tag-version` でバージョンを上げ、`package/app/app.conf` の version も同期。
2. `yarn build:prod && yarn package` で新しい `.spl` を生成。
3. Splunk Web「Install app from file」で **"Upgrade app"（上書き）にチェック**して `.spl` をアップロード。
4. `https://<host>:8000/en-US/_bump` で **Bump version** → ブラウザをハードリロード（Ctrl+Shift+R）。

### [1.2.3] - 2026-08-09

#### 修正

- **スピナーが永遠に回り続けることがある問題への対策**（全 viz 共通の横展開）。
  公式 `useDataSources` は「render 時に現在値でシード → `useEffect` で購読」の構造で、
  その間に届いた更新を取り逃す（ホストは購読登録時に現在値を再送しない）。
  サーチ完了の最終通知をこの隙間で落とすと `loading` のまま固まる。対策として、
  loading 中は `getDataSources()` を 500ms 間隔で読み直し、ホスト側が完了済みなら
  その値を採用する（`useDataSourcesWithRescue`）。完了後はポーリングしない。
  不定期・初回表示時に発生しやすく、リロードで直る症状はこれが原因とみられる。
  描画・オプションの挙動に変更はない。

`.spl`: `dist/custom_viz_treemap-1.2.3-2bb5ec3.spl`

### [1.2.0] - 2026-07-25

#### 変更

- タイルの色設定を `editor.color` 8個（`color1`〜`color8`）から **`editor.seriesColors` 1項目**（`seriesColors`）へ統合。編集画面が「プリセット選択＋色スウォッチ列」になり、色数もユーザーが増減できるようになった。
- パレットがグループ数より少ない場合は循環して適用する（既定色に落ちない）。
- `optionsSchema.seriesColors` は `anyOf`（文字列配列 ＋ DOS 文字列 `^>.*`）で宣言し、保存時検証で落ちないようにした。

#### 削除

- 旧オプション `color1`〜`color8`。**既定値が options に載らないホスト挙動のため、旧キーへのフォールバックは意図的に実装していない**（実装すると「既定値を選んだときだけ直らない」不具合になる）。既存ダッシュボードで色を変更していた場合は既定パレットに戻るので、編集画面で設定し直すこと。
- 旧オプション `debug`（「デバッグ」セクションとオプションのデバッグ表示オーバーレイ）。設定パネルからセクションごと削除した。

### [1.1.0] - 2026-07-25

#### 修正

- **グループの下辺・右辺の角丸が子タイルに潰され、直角に見えていた**のを修正。
  親の内側余白が角丸の半径より小さかったため（既定では余白 2px に対し角丸 3px）、
  子タイルの直線的な縁が親の丸みを覆い、**下端が切り落とされたように見えていた**。
  親の内側余白を `max(タイルの間隔, タイルの角丸)` に広げ、四辺とも角丸ぶんの余裕を確保した。
  実測で親と子の間隔は約 1px → 4px に改善。
  「タイルの角丸」を大きくすると内側余白も追従するため、どの設定でも角が潰れない。

#### 変更

- 入れ子の角丸を**同心円状**にした。子タイルの半径を階層ごとに 1px ずつ小さくし
  （親 3px → 子 2px）、親の丸みと平行に見えるようにした。角丸 0 のときは従来どおり直角。

#### 追加

- 角丸のクリアランスに関する検証を追加（計 93 チェック）。
  親と子の間隔が半径以上あること、半径を変えても追従すること、
  葉の半径が親より小さいこと、角丸 0 でも壊れないことを実測で検証している。

### [1.0.0] - 2026-07-25

#### 追加

- 新規作成（初回リリース）。
- 階層構造を面積で表すツリーマップ。1〜3 階層に対応し、サーチが返すラベル列の数から自動で組み立てる。
- **squarified レイアウト**（Bruls et al. 2000）の実装。タイルの縦横比を 1 に近づけ、
  slice-and-dice で生じる細長い短冊を避ける。
- **クリックによる掘り下げ**とパンくずリストによる復帰。掘り下げ位置は `drillPath` オプションに
  保存され、編集→保存で永続化できる。存在しない枝を指していた場合は全体表示へフォールバックする。
- 列の自動判定（値＝最右の数値列／階層＝非数値列を左から）と `editor.columnSelector` による明示選択。
- 第1階層で色を決め、子タイルを濃淡で塗り分ける方式（掘り下げても枝の色が変わらない）。
  パレットは色覚特性（第2色覚）に配慮した8色で、全色を編集画面で変更可能。
- タイル数の上限（既定 300）と、超過分の「その他（N件）」への集約。
- 負の値・非数値の行を除外し、件数を注記に表示。
- グループ見出し、タイル名・値・割合の表示、凡例、フェードインアニメーション。
- **ホバー時のツールチップ**（階層のパス・値・全体比・表示範囲比・内訳件数）と、
  掘り下げ可能なタイルの枠強調。ツールチップはパネル端で反対側へ折り返して見切れを防ぐ。
- **見切れ対策**：
  - パンくず・凡例・注記はいずれも SVG の外に置く独立した行なので、SVG の高さから
    それらを差し引いて渡す。**凡例ぶんの差し引き漏れとパンくずの二重計上**があり、
    既定設定でもタイル下端が約 14px 隠れていたのを修正した。
  - ラベルはタイルに入らなければ、フォント縮小 → 値の省略 → 名前の切り詰め、の順に段階退避する。
    以前は「入らなければ非表示」だったため、長い名前のタイルが無地になっていた。
  - グループ見出しは左右に同じだけ余白を確保し、「名前＋値」が入らないときは値を捨てて名前を優先する。
- `ResizeObserver` によるオートフィット、ライト／ダーク両テーマ対応、デバッグオーバーレイ。
- happy-dom によるローカル検証 `yarn verify`（85 チェック）。
  面積が値に比例すること・アスペクト比が破綻しないこと・子が親の矩形に収まることに加え、
  **パンくず／凡例／注記のどの組み合わせでもタイルが SVG に収まること**、
  **ラベルがパネル外へはみ出さないこと**、**ツールチップが端で折り返すこと**を実測で検証している。
