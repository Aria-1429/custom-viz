# Horizon Chart

Splunk **Dashboard Studio** 向けのカスタムビジュアライゼーション（React/JSX）です。

![example](examples/example.png)

---

## 概要

**多数のホストやメトリックを縦に並べ、どの系列がいつ急変したかを1画面で把握するためのグラフです。**

50台のサーバの CPU を折れ線で重ねると、線が交錯して判読が困難になります。一方、50個のパネルに
分割すると1画面に収まらず、同一時刻に何が起きたかを比較できません。
本ビジュアライゼーションは、**1系列を 20〜30px の細い帯**として縦に積み重ねることで、
50系列を1画面に収めたうえで、時間軸を揃えた比較を可能にします。

### 主な用途

| 用途 | サーチ例 |
| --- | --- |
| 多数のホストのうち、異常に急変した系列を特定する | `timechart span=5m avg(cpu) by host` |
| 障害発生時に複数メトリックが同時に変動したかを確認する | `timechart span=1m avg(latency) avg(errors) avg(qps)` |
| sourcetype ごとのログ流量の急増を検出する | `timechart span=5m count by sourcetype` |
| 増減（正負両方）の推移を確認する | `timechart span=1h sum(delta) by region` |

### 何が読み取れるか

- **色が濃いほど値が大きく、薄いほど値が小さい。** 濃い塊がある位置がスパイクです。
- **横位置は時刻を表します。** 複数レーンの濃い部分が縦に揃っていれば、それらは同時に発生したことを示します。
- **青は基準より上、赤は基準より下**（既定の基準値は 0）。増減の符号が色で判別できます。
- カーソルを合わせると全レーンを貫く縦線が表示され、その時刻の各系列の値を確認できます。

#### 色の濃さと値の対応（値が大きくなるとどう変わるか）

値が大きくなるにつれて、「薄い色が下から伸びて上端に達し、その上に1段濃い色が重なる」という順序で変化します。
**濃さと高さが同時に変化する**点が、通常の折れ線グラフとの違いです。

既定の設定（3段・1段あたり 100）における表示は次のとおりです。

| 値 | 描画される段 | 見え方 |
| --- | --- | --- |
| 20 | 1段目が 20% | **薄い色が低い位置まで**（ほとんど変化がないように見えます） |
| 100 | 1段目が 100% | **薄い色がレーン一杯**に広がります |
| 150 | 1段目 100% ＋ 2段目 50% | 薄い色の上に**中間の濃さ**が半分まで重なります |
| 300 | 3段すべて 100% | レーン全面が**最も濃い色**になります |

したがって、「**薄い色がわずかに見えるだけ**」の状態は値が小さいことを、
「**レーン全面が濃い色**」の状態はその系列で最大級のスパイクが発生していることを示します。

薄い色の濃さ（既定 0.28）は、編集画面の「最下バンドの濃さ」で調整できます。
値を下げるほど小さい値が目立たなくなり、スパイクのみが際立ちます。

#### 1つのレーン内で色が混在する理由

**1本のレーンの中に薄い部分と濃い部分が混在するのは正常な表示です。**
レーンは横方向が時間軸であるため、**時刻ごとに値が異なれば、到達する段が変わり、その位置の色も変わります**。

同一レーン内での時刻ごとの変化の例（既定の 3段・1段あたり 100）:

| 時刻 | 値 | 到達する段 | その位置の色 |
| --- | --- | --- | --- |
| 00:00 | 20 | 1段目が 20% | 薄い色が低い位置まで |
| 01:00 | 90 | 1段目が 90% | 薄い色が高い位置まで |
| 02:00 | 150 | 1段目 100% ＋ 2段目 50% | **中間の濃さ** |
| 03:00 | 300 | 3段すべて 100% | **最も濃い色** |
| 04:00 | 60 | 1段目が 60% | 薄い色が低い位置まで |

つまり、**濃くなっている箇所は「その時刻に値が大きかった」ことを示します**。
1つのレーン内に薄い部分と濃い部分が混在している場合、それは
**平常時（薄い）とスパイク発生時（濃い）が混在している**状態を表します。

この性質により、次のように読み取ります。

- **横方向に濃い箇所を探す** → その系列が**いつ**急変したかが分かります
- **レーンをまたいで縦に見る** → 複数の系列が**同時に**急変したかが分かります

なお、レーン全体が一様に薄い場合は、その期間を通じて値の変動が小さかったことを示します。
逆にレーン全体が一様に濃い場合は、「1バンドの幅」が小さすぎる可能性があります
（「うまく表示されないとき」を参照）。

## 仕組み（レーンを細くできる理由）

折れ線グラフは値の大きさを線の高さで表現するため、値域が広いほど縦方向の領域を必要とします。
ホライズンチャートは**値の大きさを「高さ」ではなく「色の濃さ」で表現する**ことで、この制約を回避します。

グラフを上から数段に分割し、**上の段を下へ折り返して重ね、上の段ほど濃く塗ります**。

```
通常の折れ線（高さ H が必要）        ホライズン（高さ H/3 で同じ情報量）

     ╱╲                              ■■■  ← 3段目（最も濃い＝最も高い値）
    ╱  ╲          折り返して重ねる    ▨▨▨  ← 2段目
   ╱    ╲    ────────────────────>   ░░░  ← 1段目（最も薄い＝低い値）
  ╱      ╲
 ╱        ╲
```

3段に折り返せばレーンの高さは 1/3 で済み、その分だけ多くの系列を並べられます。
段数は編集画面で 1〜6 段に変更できます。**段数を増やすほどレーンを細くできる一方、色の判別は難しくなります**。
既定の 3 段が実用上のバランスの取れた設定です。

> **標準ビジュアライゼーションでは代替できません。** 標準の Area/Line は系列数に限界があり、
> Punchcard はドットサイズの離散表現、Heat Matrix（別 viz）は時刻を離散セルに落とすため
> 時系列の波形が失われます。

## データ仕様

**基本的には `timechart` の結果をそのまま利用できます。** 列の割り当ては自動判定されるため、
通常は編集画面での設定は不要です（自動判定が意図と異なる場合のみ「データフィールド」で明示指定します）。

対応する形式は次の 2 種類で、いずれかが**自動的に判別されます**。

### 1. クロス集計（wide）— `timechart` の出力そのまま

| 第1列（時刻） | 第2列以降（数値＝各系列） |
| --- | --- |
| `_time` | `web-01`, `web-02`, `db-01` … |

```spl
index=_internal | timechart span=5m count by sourcetype
```

### 2. 縦持ち（tidy）— 時刻・系列名・値の3列

| 時刻列 | 系列ラベル列 | 数値列 |
| --- | --- | --- |
| `_time` | `host` | `count` |

```spl
index=_internal | bin _time span=5m | stats count by _time, host
```

同一の (時刻, 系列) の組み合わせが複数行存在する場合は**合算**されます。

### 時刻フィールドの解釈

`_time` のほか、以下の形式を自動的に解釈します。

- epoch 秒（10桁前後）／epoch ミリ秒（13桁前後）
- ISO 形式（`2026-07-20T10:00:00` / `2026-07-20 10:00:00`）
- 日付のみ（`2026-07-20`）… UTC とのずれを避けるため、ローカル日付として解釈します
- 時刻列が検出されない場合は、第1列を順序インデックスとしたカテゴリ軸にフォールバックします

## 編集画面のオプション

**最初に調整するとよい 3 項目**です（他の項目は既定値のままで支障ありません）。

| 困っていること | 変えるオプション |
| --- | --- |
| 系列が多くて画面に収まらない | **バンド数**を増やす（3→5）／**最大表示系列数**を絞る |
| 特定の1系列だけ突出して他が真っ白 | **系列ごとに高さを正規化**を on |
| 値が高い水準で平坦に推移し変動が読めない | **系列ごとに高さを正規化**を on |
| 問題のある系列を特定したい | **並び順**を「最大値順」にする |

> **補足：1バンドの幅の自動計算**
> 「最大値 ÷ バンド数」を、切りのよい値（1/2/5×10ⁿ）へ**切り下げ**て決定します。
> 切り上げた場合、最上バンドが最後まで埋まらず、レーン上部に常に余白が生じるためです
> （例：最大 300 ÷ 3 段の場合、切り上げて 500 とするとピークが 60% までしか伸びません）。
> 切り下げが過大となり階調が失われる場合（最上バンドの充填率が 50% 未満）は、厳密な等分に自動で切り替わります。

## サンプル SPL

以下の SPL をそのまま貼り付けて動作を確認できます。
実データがなくても実行可能です（Splunk 9.0 以降の `makeresults format=csv` を使用）。

### 多系列のスパイク比較（wide 形式）

```spl
| makeresults format=csv data="_time,web-01,web-02,web-03,db-01,db-02
2026-07-20 00:00:00,10,12,8,120,95
2026-07-20 01:00:00,12,15,9,130,102
2026-07-20 02:00:00,11,14,300,125,98
2026-07-20 03:00:00,45,13,9,128,410
2026-07-20 04:00:00,180,16,10,132,105
2026-07-20 05:00:00,20,14,9,127,99
2026-07-20 06:00:00,13,15,8,124,101"
| eval _time=strptime(_time,"%Y-%m-%d %H:%M:%S")
```

**表示結果**：5本のレーンが縦に並び、`web-03`（02:00）・`db-02`（03:00）・`web-01`（04:00）の
3か所のみ色が濃くなります。**濃い部分が縦に揃っていないことから、別々の時刻に発生したスパイク**であると読み取れます。
カーソルを合わせると縦線が表示され、その時刻の値を確認できます。

### 増減（負値あり・基準値 0）

```spl
| makeresults format=csv data="_time,revenue_delta,cost_delta
2026-07-20 00:00:00,120,-40
2026-07-20 01:00:00,-80,30
2026-07-20 02:00:00,200,-90
2026-07-20 03:00:00,-150,60
2026-07-20 04:00:00,90,-20"
| eval _time=strptime(_time,"%Y-%m-%d %H:%M:%S")
```

**表示結果**：`revenue_delta` と `cost_delta` の2レーンが表示されます。正の値の時刻は青、負の値の時刻は赤で
描画され、両者が**逆方向に変動している**（一方が青のとき他方が赤）ことを一目で確認できます。

### 縦持ち（tidy 形式）

```spl
| makeresults format=csv data="_time,host,count
2026-07-20 00:00:00,h1,10
2026-07-20 00:00:00,h2,40
2026-07-20 01:00:00,h1,25
2026-07-20 01:00:00,h2,80
2026-07-20 02:00:00,h1,60
2026-07-20 02:00:00,h2,35"
| eval _time=strptime(_time,"%Y-%m-%d %H:%M:%S")
```

**表示結果**：`h1` / `h2` の2レーンが表示されます。wide 形式とは異なり「時刻・系列名・値」の3列構成ですが、
形式は自動判別されるため設定は不要です。

### 実データでの利用例

どのソースタイプのログ流量が急増したかを確認する例です（自身の環境でそのまま実行できます）。

```spl
index=_internal | timechart span=5m count by sourcetype limit=30
```

ホストごとの CPU 推移を確認する例です（縦持ち形式）。

```spl
index=_internal | bin _time span=10m | stats avg(cpu_seconds) as cpu by _time, host
```

## うまく表示されないとき

| 症状 | 原因と対処 |
| --- | --- |
| 「データがありません」と表示される | 時刻列と数値列が必要です。`timechart` を使用するか、`_time` を含む結果にしてください。パネル内に補足のヒントが表示されます |
| 1系列のみ濃く、他が白いまま | 系列ごとに値の桁が異なることが原因です。**「系列ごとに高さを正規化」を on** にしてください |
| レーンが濃い色で塗り潰され変動が見えない | 値が 0 から離れた高い水準で推移している場合に起こります。**「系列ごとに高さを正規化」を on** にすると、その系列の変動幅が全段に展開されます |
| 全体が濃すぎて塗り潰されて見える | 全系列が最上バンドに達しています。**「1バンドの幅」を大きく**するか、バンド数を増やしてください |
| 系列が途中までしか表示されない | 既定の**最大表示系列数（60）**を超えています。画面下の注記を確認のうえ、値を引き上げるか、SPL 側で `limit` を指定して絞り込んでください |
| 系列名が「…」で省略される | **「系列名の幅」**を px 単位で指定するか、パネルの幅を広げてください |
| 編集画面で設定が反映されない | `.spl` のバージョンを上げて Upgrade → `_bump` → ハードリロードを実施してください（下記デプロイ手順を参照） |

## 開発コマンド

```bash
yarn install
yarn build      # dist/custom_viz_horizon_chart/visualization.js を生成（esbuild）
yarn verify     # happy-dom によるローカル検証（Splunk 実機不要・105 チェック）
yarn package    # dist/*.spl を生成
```

## デプロイ（アンインストール・再起動なし）

1. `npm version <patch|minor> --no-git-tag-version` でバージョンを上げ、`package/app/app.conf` の version も同期。
2. `yarn build:prod && yarn package` で新しい `.spl` を生成。
3. Splunk Web「Install app from file」で **"Upgrade app"（上書き）にチェック**して `.spl` をアップロード。
4. `https://<host>:8000/en-US/_bump` で **Bump version** → ブラウザをハードリロード（Ctrl+Shift+R）。

## 設計メモ

- **完全オフライン**：外部 API フェッチ・CDN 読み込みなし。依存はすべてバンドルに同梱。
- **マウントゲート**：ホスト初期化完了を待ってから `createRoot().render()`（初期 state の取り逃し対策）。
- **データ正規化**：`rows` / `columns` 両形式に対応。マルチバリューセルはトークン数一致時に平行展開。
- **値→色**：`editor.dynamicColor` はカスタム viz で使用できないため、バンド不透明度による濃淡を自前実装。
- **オートフィット**：`ResizeObserver` でコンテナ実寸を測り、レーン高さを配分。収まらなければ縦スクロール。
- **描画上限**：系列は `maxSeries`（既定 60・上限 200）、時刻点は 2000 点で間引き。省略時は注記を表示。
- 編集画面のオプションラベルはすべて日本語（キー名は英語）。
- 使用している editor 型は実機確認済みの 4 種のみ（`color` / `checkbox` / `number` / `columnSelector`）。

  従来は「最大値の大きい順に並べ替え」（`sortByPeak`）と「合計の大きい順に並べ替え」（`sortByTotal`）が
  独立したチェックボックスで、**両方 ON にできてしまう**が実際の動作は未定義だった
  （コードが `if / else if` のため最大値順が黙って優先されていた）。
  選択肢は「検索結果順（`none`、既定）／最大値順（`peak`）／合計順（`total`）」の排他 3 択となり、
  UI 上も矛盾した状態を作れなくなった。
- 未知の値（旧バージョンの残骸など）は既定の「検索結果順」へ丸めるようにした。

> **⚠ 並び順の設定は既定値に戻ります。再度選び直してください。**
> 旧オプション（`sortByPeak` / `sortByTotal`）からの読み替えは**意図的に実装していません**。
> ホストは `optionsSchema` の既定値と同じ値を options に載せないことがあるため、
> 旧オプションへフォールバックすると「既定値を選んだときだけ旧設定が復活して直らない」という
> 分かりにくい不具合になります。既存ダッシュボードでは旧チェックボックスの値は完全に無視され、
> 「検索結果順」で表示されます。

#### 削除

- **デバッグ表示オプション（`debug`）と、それに紐づく「デバッグ」セクション・
  画面右下のオーバーレイを削除。** 併せて、オーバーレイ専用に組み立てていた
  内部の列インデックス情報（`usedIdx`）も削除した。
- 旧オプション `sortByPeak` / `sortByTotal` を `optionsSchema` から削除。

#### 成果物

- 検証を計 120 チェックに更新（旧 boolean が無視されることの回帰テスト、
  最大値順と合計順で並びが実際に変わることの確認、デバッグ表示が出ないことの確認を追加）。

### [1.0.1] - 2026-07-25

#### 修正

- **「系列ごとに高さを正規化」が、0 から離れた水準で推移する系列で破綻していた問題を修正。**
  従来は基準を 0（または `bandBase`）に固定したまま「最大値 ÷ 段数」でバンド幅を決めていたため、
  値が常に高い水準にある系列（例：120〜132）では平常値でも下位バンドが満杯となり、
  レーンが塗り潰されて変動を読み取れなかった（120〜132 の系列で 1段=44 となり、平常値 120 が
  2.7 段ぶんに達していた）。
  正規化時は**基準をその系列の最小値、1段の幅を「変動幅 ÷ 段数」**とし、
  最小〜最大が全段に展開されるよう変更。わずかな変動も薄→濃のグラデーションとして読める。
- 正規化時の凡例表記を修正。基準・バンド幅が系列ごとに異なるため、固定値の「1段=N・基準=M」ではなく
  「各レーンの最小〜最大を N 段に展開」と表示する。
- 正規化時、レーンのツールチップに最小値とそのレーンの基準値を併記するようにした。
- 変動がゼロの系列（全時刻が同値）を正規化した場合に、バンドを描画せず平坦に扱うガードを追加。

#### 追加

- 上記の回帰防止テスト 7 件（最小値が基準に来ること・最大値が全段を満たすこと・
  下位バンドが常時飽和しないこと・変動ゼロ系列の安全性など）。検証は計 112 チェックに。
- 生成した `.spl`：`dist/custom_viz_horizon_chart-1.0.1-d5418cf.spl`

### [1.0.0] - 2026-07-25

- 系列名・各レーンの最大値・時刻軸・凡例の表示切替、曲線／折れ線の切替、描画アニメーション。
- ライト／ダーク両テーマ対応、`editor.columnSelector` によるフィールド明示選択（DOS 文字列を自前解決）。

  クロスヘア・ガード・テーマ切替を含む）。
