# Sankey Flow
![表示例](examples/example.png)

Splunk Dashboard Studio 向けのカスタムビジュアライゼーション（Sankey フロー図・多段対応）。

ネットワークトラフィックの経路、ユーザーの画面遷移、売上の内訳フローなど、
**「どこから、どこへ、どれだけ流れたか」** を帯の太さで表す。

## 標準 `splunk.sankey` との違い

Dashboard Studio には標準の Sankey（`splunk.sankey`）がある。**まず標準で足りないか確認すること。**
下表は実機（Splunk Enterprise 10.4.2）のバンドルから標準のオプションスキーマを抽出し、
同一データで並べて描画を比較した結果（2026-08-09 実機確認済み）。

**標準のオプションは7個だけ**：`backgroundColor` / `colorMode` / `linkColors` /
`linkOpacity` / `linkValues` / `resultLimit` / `seriesColors`。

| できること | 標準 `splunk.sankey` | この viz |
|---|---|---|
| **4列以上の多段フロー** | ❌ **3列目以降を黙って捨てる**（実機確認済み） | ✅ 列がそのまま段になる |
| 経路の追跡（上流〜下流を一括強調） | ❌ | ✅ `traceMode` |
| クリックでトークン設定（ドリルダウン） | ✅ | ✅ ノード／リンクの両方 |
| 段ごとの損失・離脱の可視化 | ❌ | ✅ `showLoss` |
| 上位N件に集約（残りを「その他」へ） | ❌（`resultLimit` は単純な打ち切り） | ✅ `topN` |
| しきい値で色分け | △ DOS 式が必要 | ✅ `editor.threshold` で GUI 設定 |
| 段内の並び順 | ❌ | ✅ `nodeSort` |
| ノード幅・間隔 | ❌ | ✅ |
| 値の単位表示 | ❌ | ✅ `valueUnit` |
| リンク上の値ラベル | ❌ | ✅ 重なりを自動回避 |
| 循環リンク | ❌ | ✅ 除去／段を増やして残す |
| サマリー（総流量・段数・損失率） | ❌ | ✅ |

> **⚠ 最も重要な差**：標準は `stats sum(x) by f1 f2 f3` のような**多段データを渡すと
> 3列目以降が消える**。エラーも警告も出ないため、**段が減っていることに気づけない**。

## 特徴

- **2つの入力モード**
  - 3列 `source, target, value` … 自由グラフモード。`a→b`, `b→c` を行として並べれば多段の連鎖になる。循環リンク（`c→a` など）は値の小さいものから自動除去。
  - 4列以上 `stage1, stage2, ..., value` … ステージモード。列がそのまま段になり、各行がパス全体に値を流す（`stats sum(x) by f1 f2 f3` の結果をそのまま入れられる）。
- **リンクの配色 3方式**（`colorMode`）
  - `categorical` … ソースノード色→ターゲットノード色の SVG グラデーション（既定）
  - `scale` … 低値色→(中間色)→高値色の自前カラースケール（連続グラデーション）
  - `threshold` … **`editor.threshold` で「範囲→色」を GUI から追加**（配列が生で届く。`editor.dynamicColor` はカスタム viz では使えないため）
- **経路の追跡**（`traceMode`）… ノードにホバーすると、**その先・その手前まで経路全体**を光らせる。多段フローで「どこから来てどこへ抜けたか」が1目で分かる（経路全体／隣接のみ／強調しない の3択）
- **ドリルダウン** … ノード／リンクのクリックでトークンを設定できる（編集画面の「インタラクション」で設定する）
- **段ごとの損失の可視化**（`showLoss`）… 入った量と出た量の差を帯で表示し、ヘッダーに損失率を出す。**ファネルの離脱・パケットロスの分析**に使う
- **上位N件への集約**（`topN`）… 段ごとに上位 N 件を残し、残りを「その他」にまとめる。単純な打ち切りと違い**総量が保たれる**
- **ノードの並び順**（`nodeSort`）… 自動（交差を減らす）／値の大きい順／名前順
- **単位表示**（`valueUnit`）… `bytes`・`人`・`%` などを値に添える（前置き／後置き）
- **リンク上の値ラベル**（`showLinkLabels`）… 太い帯にだけ値を出す。**重なる場合はずらして両方表示する**（値を消さない）。帯の外へ逃がしたときは引き出し線でどのリンクの値か示す
- **循環リンクの扱い**（`cycleMode`）… 除去する／段を増やして残す
- **ホバーハイライト** … ツールチップに値・全体比・入出次数・損失を表示
- **サマリーヘッダー** … 総流量・段数・ノード数・リンク数・損失・集約数・除去した行数を表示
- **オートフィット** … ResizeObserver でコンテナ実寸に追従。ラベルは細いノードで自動的に隠す
- **堅牢性** … rows/columns 両形式、カンマ付き数値、空カテゴリ・非数値・0以下の行、空データ、テーマ未取得をすべてガード。同一 (source, target) は合算。リンクは値の大きい順に最大500本
- ライト/ダークテーマ対応。ノード色は Splunk 配色に寄せた12色パレット（同名ノードは段が違っても同色）

## データ仕様

| 列 | 内容 |
|---|---|
| 最終列 | 数値（フロー量）。カンマ付き文字列も可。0以下・非数値の行は無視 |
| それ以外の列 | 経路のステージ（カテゴリ文字列）。空欄の行は無視 |

## オプション（ダッシュボード編集画面）

| セクション | 項目 |
|---|---|
| リンク | リンクの配色（ノード色／値のグラデーション／しきい値）/ グラデーションリンク / 不透明度(%) / 低・中間・高の色 / 3色スケール / 反転 / **しきい値の色**（範囲を + で追加） |
| ノード | **ノードの色**（パレット）/ 幅(px) / 間隔(px) / **段内の並び順** |
| ラベル | ノード名 / 値の併記 / **リンクに値を表示** / 文字サイズ(0=自動) / **単位** / **単位の位置** |
| 分析 | **ホバー時の強調範囲**（経路追跡／隣接／なし）/ **上位N件に集約** / 集約先の名前 / **段ごとの損失** / 損失の色 / **循環リンクの扱い** |
| 表示 | サマリーヘッダー / ホバーハイライト |

**ドリルダウン**：編集画面の「インタラクション」で設定する。ノードは `row.<最初の列名>.value`、
リンクは `row.<最初の列名>.value` と `row.<最後から2番目の列名>.value`・`row.<値列名>.value` を渡す。

## 開発

```bash
yarn install
yarn build      # dist/custom_viz_sankey_flow/visualization.js
yarn package    # dist/custom_viz_sankey_flow-<ver>-<hash>.spl
```

依存: レイアウトは `d3-sankey`（純粋な計算ライブラリ。バンドルに同梱され、実行時のネットワーク通信は一切なし）。

## デプロイ（アンインストール・再起動不要）

1. `npm version patch --no-git-tag-version` でバージョンを上げ、`package/app/app.conf` の `version` も同期
2. `yarn build:prod && yarn package`
3. Splunk Web「Install app from file」で **Upgrade app にチェック**して `.spl` をアップロード
4. `https://<host>:8000/en-US/_bump` で Bump version → ブラウザをハードリロード (Ctrl+Shift+R)

## サンプル SPL

### 3列（自由グラフモード）— ネットワークフロー

```spl
| makeresults format=csv data="source,target,bytes
Internet,Firewall,5200
Internet,VPN,1400
Firewall,Web Server,3600
Firewall,App Server,1500
VPN,App Server,900
Web Server,Database,2100
App Server,Database,1700"
| table source target bytes
```

### 4列（ステージモード）— 売上フロー

```spl
| makeresults format=csv data="region,product,channel,revenue
APAC,Widgets,Online,120
APAC,Widgets,Retail,60
APAC,Gadgets,Online,80
EMEA,Widgets,Online,90
EMEA,Gadgets,Retail,70
AMER,Gadgets,Online,140
AMER,Widgets,Retail,50"
| table region product channel revenue
```

### ファネルの離脱分析（`showLoss` を ON にする）

各段で「入った量」より「出た量」が少ないと、その差が損失として帯で表示される。

```spl
| makeresults format=csv data="step1,step2,users
訪問,カート投入,4200
カート投入,決済画面,2600
決済画面,購入完了,1400"
| eval users=tonumber(users)
| table step1 step2 users
```

### 多段フロー（標準 `splunk.sankey` では3列目以降が消える例）

```spl
index=web sourcetype=access_combined
| stats sum(bytes) as bytes by region, product, channel
| table region product channel bytes
```

### 実データの例

```spl
index=web sourcetype=access_combined
| stats sum(bytes) as bytes by src_ip, dest_ip
| sort - bytes | head 50
| table src_ip dest_ip bytes
```

### [2.0.1] - 2026-08-09

#### 修正

- **リンクの値ラベルが重なるときに、片方が消えていたのを修正**（v2.0.0 の実装ミス）。
  v2.0.0 では「重なったら値の大きい方だけ残す」間引きにしていたが、
  **消えたのか元々値が無いのかを利用者が区別できない**（標準 `splunk.sankey` が
  段を黙って捨てるのと同じ問題を作っていた）。
  ずらして**両方表示する**方式に変更した:
  1. そのまま置ければそのまま
  2. 帯の内側で上下にずらす
  3. それでも無理なら帯に沿って左右にずらす
  4. 逃げ場が無ければ帯の外に出し、**引き出し線**でどのリンクの値か示す
  → **ラベルを消す経路を無くした**。回帰テストで「間引かれないこと」「同一座標に
  重ならないこと」を検査している。

### [2.0.0] - 2026-08-09

**標準 `splunk.sankey` に対する優位性を明確にするための大型更新。**
実機のバンドルから標準のオプションスキーマを抽出して比較したうえで、
標準に無い機能を追加した（README 冒頭の比較表を参照）。

#### 追加

- **ドリルダウン**（`showDrilldown` / `hasEventHandlers` / `events` を有効化）。
  ノード（`node.click`）とリンク（`link.click`）のクリックでトークンを設定できる。
  発火は `addDrilldownListener` に登録した DOM ノードのクリックのみ（`triggerDrilldown` は効かない）。
  登録はノード1つにつき1回とし、payload は WeakMap で差し替えるため、
  並べ替えや集約のあとでも「その位置に表示されている要素」の値が飛ぶ。
- **経路の追跡**（`traceMode`）。ノードのホバーで上流〜下流の経路全体を強調する。
  `path`（既定）/ `adjacent` / `off`。
- **段ごとの損失の可視化**（`showLoss` / `lossColor`）。
  ノードに入った量と出た量の差を帯で描き、ヘッダーに総損失と損失率を出す。
- **上位N件への集約**（`topN` / `otherLabel`）。段ごとに上位 N 件を残し、
  残りを「その他」ノードにまとめる（総量が保たれる）。
- **しきい値による色分け**（`colorBands`、`editor.threshold`）。
  範囲＋色の配列が生で届くため、GUI から「範囲を + で追加」できる。上端開放（`to: null`）に対応。
- **ノードの色パレット**（`nodeColors`、`editor.seriesColors`）。
- **段内の並び順**（`nodeSort`）… 自動 / 値の大きい順 / 名前順。
- **単位表示**（`valueUnit` / `unitPosition`）。
- **リンク上の値ラベル**（`showLinkLabels`）。近接するラベルは自動で間引く。
- **循環リンクの扱い**（`cycleMode`）… 除去する / 段を増やして残す。

#### 変更

- **`useValueColors`（チェックボックス）を `colorMode`（ドロップダウン）に置き換えた**（破壊的変更）。
  配色方式が3つになり、排他的な選択をチェックボックスで表現できなくなったため。
  **旧オプションへのフォールバックは意図的に実装していない**（既定値は options に載らないため、
  フォールバックすると「既定値を選んだときだけ直らない」不具合になる）。
  → **リンクの配色を設定していた場合は選び直すこと。**

#### 修正

- リンク値ラベルが近接時に重なって読めなくなる問題（実機で確認）。
  太さだけでなく**ラベル同士の距離**で判定し、値の大きい方を優先して出すようにした。

#### 検証

- ローカル検証（`yarn verify`）を 29 件 → **61 件**に拡充。
  しきい値色・単位・並び順・集約・循環展開・損失・リンクラベル・ドリルダウン登録・
  経路追跡・**旧オプションが復活しないこと**を回帰テストにした。
- 実機（Splunk Enterprise 10.4.2）で標準 `splunk.sankey` と並べて描画を確認済み。
  **標準は4列以上のデータで3列目以降を黙って捨てる**ことを実機で確認した。

`.spl`: `dist/custom_viz_sankey_flow-2.0.0-fe61813.spl`

### [1.1.3] - 2026-08-09

#### 修正

- **スピナーが永遠に回り続けることがある問題への対策**（全 viz 共通の横展開）。
  公式 `useDataSources` は「render 時に現在値でシード → `useEffect` で購読」の構造で、
  その間に届いた更新を取り逃す（ホストは購読登録時に現在値を再送しない）。
  サーチ完了の最終通知をこの隙間で落とすと `loading` のまま固まる。対策として、
  loading 中は `getDataSources()` を 500ms 間隔で読み直し、ホスト側が完了済みなら
  その値を採用する（`useDataSourcesWithRescue`）。完了後はポーリングしない。
  不定期・初回表示時に発生しやすく、リロードで直る症状はこれが原因とみられる。
  描画・オプションの挙動に変更はない。

`.spl`: `dist/custom_viz_sankey_flow-1.1.3-2bb5ec3.spl`
