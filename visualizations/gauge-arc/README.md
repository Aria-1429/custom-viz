# Custom Viz Gauge Arc

![表示例](examples/example.png)

Splunk Dashboard Studio 向けのカスタムビジュアライゼーション（単一値のアークゲージ）。

**主役は「1つの数値」**。円弧ゲージで現在値を大きく見せつつ、右（左／下）のサブ情報パネルに
前回比・サブ指標・内訳・推移などを添える。標準の SingleValueRadial は単色リング1本で色帯を持てず、
MarkerGauge は横長の棒なので、「色帯を持つ半円ゲージ＋周辺情報」はこの viz でしか作れない。

## 特徴

- **ゲージの種類を切り替えられる**（`editor.radioBar`）
  - **連続**: なめらかな1本の弧。値の位置まで塗る。帯の境界で色が切り替わる
  - **セグメント**: 弧を N 個の小片に割り、値の位置まで点灯するイコライザ風。
    点灯色は「各セグメントが自分の位置の帯色」／「現在値の色で統一」から選択
  - **タコメーター**: 帯を全周ぶん常時塗り、**針で現在値を指す**車のメーター風。
    針と重ならないよう数値・タイトルは中央下へ自動でずれる
- **開き角を選べる**: 半円（180°）／標準（240°）／広め（280°）／ほぼ全周（320°）
- **値の範囲と色**（`editor.threshold`）で帯を何段でも追加でき、各帯が自分の色を持つ。
  上限／下限なしの開いた範囲も可。単色モードにも切り替えられる
- **色が切り替わる位置に数値を表示**（帯の境界値）。弧の外側に放射状に配置し、
  近すぎるラベルは自動で間引く。最小値・最大値のラベルも見切れないよう外側へ逃がす
- **前回との比較**を差分＋割合で表示。比較の相手は
  **直前の行／最初の行／現在を除く平均／指定フィールド／固定値**から選べる。
  「増加が良い／減少が良い」に応じて色分け（達成率の指標と障害件数の指標で色の意味が逆転する問題に対応）
- **サブ情報パネルは 4 スロット**。各スロットの中身をドロップダウンで選ぶ:
  前回比 / サブ指標 / 帯ごとの件数内訳 / 上位ランキング / 推移（スパークライン） /
  目標との比較 / 帯の凡例 / 対象期間・更新時刻 / 自由テキスト
- **中央の数値の色**を選べる: ゲージと同じ色（値の範囲で変わる）／固定色／自動（テーマの文字色）
- **ゲージの値の決め方**を選べる: 最終行 / 先頭行 / 合計 / 平均 / 最大 / 最小 / 件数
- 目盛り・針・目標線・発光（グロー）・アニメーションの有無を個別に設定
- **オートフィット＋段階退避**: 幅が狭ければパネルを下へ回し、さらに狭ければゲージのみにする。
  その場合も前回比だけは中央下に残す
- ライト／ダークテーマ対応。空データ・型不一致・カンマ付き数値・マルチバリューに対するガード処理
- 設定はすべて `useOptions` 経由。編集画面のラベルは日本語

## データ仕様

1 行 = 時系列またはカテゴリの 1 ポイント（行順が古 → 新）。

| 列 | 役割 | 既定 |
|---|---|---|
| ラベル列 | 名前・時刻。ランキング／推移に使用 | 第1列 |
| 値列 | 数値。ゲージの値と各種集計に使用 | 最終列 |

- 「ゲージの値の決め方」が `最終行` のとき、**最終行の値**がゲージの値になり、
  **直前の行**が既定の比較対象（前回値）になる。
- 1列だけのデータはその列を値列として扱う。
- `columns` 形式でデータが届いた場合も `rows` 形式と同様に処理する。

## サンプル SPL

### 1. CPU 使用率の推移（既定の設定でそのまま動く）

```spl
| makeresults format=csv data="time,cpu
10:00,41
10:05,55
10:10,63
10:15,72
10:20,87"
```

最終行 `87` がゲージの値（既定帯では 85+ = 危険＝赤）、直前の `72` との差 `+15 (+20.8%)` が前回比に出る。

### 2. SLA 達成率（減少が悪い指標。目標線つき）

```spl
| makeresults format=csv data="date,sla
07-21,99.4
07-22,99.1
07-23,98.7
07-24,99.2
07-25,97.6"
```

設定例: 最小値 `95` / 最大値 `100` / 単位 `%` / 小数点以下 `1` /
値の範囲と色を `〜98=赤 / 98〜99=橙 / 99〜=緑` / 望ましい変化の向き＝**増加が良い** /
目標線を表示・目標値 `99.5`。

### 3. ホスト別のエラー件数（ランキング＋内訳を出す）

```spl
| makeresults format=csv data="host,errors
web-01,12
web-02,48
api-01,7
api-02,91
db-01,25"
```

設定例: ゲージの値の決め方＝**合計** / 最大値 `200` /
1段目＝上位ランキング / 2段目＝帯ごとの件数内訳 / 3段目＝サブ指標 /
望ましい変化の向き＝**減少が良い**。

### 4. セグメント表示（イコライザ風）

```spl
| makeresults format=csv data="t,v
1,20
2,35
3,52
4,68"
```

設定例: ゲージの種類＝**セグメント** / セグメントの数 `28` / 隙間 `30` /
点灯セグメントの色＝各セグメントが自分の位置の帯色。

### 5. タコメーター表示（針が現在値を指す）

```spl
| makeresults format=csv data="t,rpm
1,1200
2,2600
3,4100
4,5200"
```

設定例: ゲージの種類＝**タコメーター** / 最小値 `0` / 最大値 `8000` / 単位 `rpm` /
開き角 `280°` / 値の範囲と色を `〜5000=緑 / 5000〜6500=橙 / 6500〜=赤`。
帯が全周ぶん塗られ、針が最終行の `5200`（＝橙帯）を指す。数値は針と重ならないよう中央下に出る。

## 開発コマンド

```bash
yarn install
yarn build      # dist/custom_viz_gauge_arc/visualization.js を生成
yarn verify     # happy-dom によるローカル検証（実機なしで 122 項目）
yarn package    # dist/custom_viz_gauge_arc-<ver>-<hash>.spl を生成
```

## デプロイ

アンインストール・再起動は不要。

1. `package.json` と `package/app/app.conf` の `version` を上げ、`yarn build && yarn package`
2. Splunk Web「Install app from file」で **"Upgrade app"（上書き）にチェック**して `.spl` をアップロード
3. `https://<host>:8000/en-US/_bump` を開いて **Bump version**
4. ブラウザをハードリロード（Ctrl+Shift+R）

反映されない場合はリバースプロキシ（Cloudflare トンネル）のキャッシュを疑う。

## 注意

- **既定値と同じ値は options に載らない**というホストの仕様があるため、オプションのキー名を
  変更した場合、旧キーへのフォールバックは実装していない（実装すると「既定値を選んだときだけ
  直らない」不具合になる）。設定は選び直すこと。
- **開き角（`sweepAngle`）は `editor.select` の value に数値を使っている**。数値 value の
  `editor.select` はこのリポジトリで初採用のため、実機で選択が反映されるかは要確認
  （viz 側は数値・文字列のどちらで届いても動くよう実装済み）。
- **「サブ指標に出す統計」はチップ入力（`editor.arrayOfStrings`）のまま**。複数チェックボックス化は
  `editor.columnMultiSelectionByFieldNameEditor` が任意の選択肢を受け付けるか次第で、
  実機検証待ち（`visualizations/editor-probe/ROUNDS.md` の ROUND 12）。

### [1.2.0] - 2026-07-26

#### 追加

- **中央の数値の色を設定できるようにした**（`valueColorMode`）。3 モードから選ぶ:
  - **ゲージと同じ色**（既定）… 値の範囲（`editor.threshold` の帯）で決まる色に追従する。
    値が変われば数値の色も変わる。単色モードのときはその色になる
  - **固定色**… `valueFixedColor` で指定した色。値が変わっても色は変わらない
  - **自動**… テーマ標準の文字色（ダークで明るいグレー／ライトで黒に近い色）
  数値の発光（グロー）の色も選んだ色に追従する。
  なお帯の色をそのまま大きな文字に使うと、濃い色はダークテーマで沈み、明るい色はライトテーマで
  飛ぶため、**可読性を保つようテーマに応じて白／黒側へわずかに寄せて**描画する。

#### その他

- ローカル検証を 110 → **120 項目**に拡充（3 モードの色・値変更への追従・
  固定色が値に影響されないこと・ライト/ダーク両テーマ・不正値のフォールバックを検証）。

### [1.1.1] - 2026-07-26

#### 修正

- **ゲージ下の余白が大きすぎ、ゲージが不必要に小さくなる問題を修正**。
  弧の外接矩形の下端を「開き角が 180°以上なら常に `1`（＝真下まで届く）」と決め打ちしていたため、
  例えば開き角 240°（実際の下端は `0.5r`）では**縦幅を 33% 過大に見積もり**、
  その分だけ下に余白ができて半径も小さくなっていた。下端を端点の角度から正しく求めるようにした。
  同条件（560×400 / 240°）で **半径 177.8 → 216.0（+22%）／下の余白 111px → 38px（−66%）**。
- **ゲージ上部の数値（頂点に来る境界値）が見切れる問題を修正**。
  中心位置の計算で上側に `labelPad * 0.5` しか確保していなかったが、ラベルは
  `rOuter + フォント*0.75` の位置に描かれるため上へはみ出していた。
  弧＋上下ラベルを1つの塊として扱い、その塊をゲージ領域の中央に置くようにした。
- **サブ情報パネルを「下」にしたとき、余白が大きくゲージが小さくなる問題を修正**。
  パネル高さを「全体の 34〜45%」という固定比率で確保していたため、スロットが1つでも
  大きな領域を取っていた。**各スロットの行数から必要な高さを見積もる**方式に変更
  （上限は従来どおり 45%）。1スロットならゲージが全体の 65% 以上を保つ。

#### その他

- ローカル検証を 99 → **110 項目**に拡充。SVG のパスとテキストから実際の描画範囲を測り、
  **上下にはみ出さないこと**・**下の余白が過大でないこと**を開き角 4 種すべてで検証する
  回帰テストを追加（今回の不具合を再発させないため）。
- 生成した `.spl`: `dist/custom_viz_gauge_arc-1.1.1-a450cdf.spl`

### [1.1.0] - 2026-07-26

#### 追加

- **ゲージの種類に「タコメーター」を追加**。帯を全周ぶん常時塗り、針で現在値を指す車のメーター風。
  針が数値に重ならないよう、中央のテキストを自動で下へずらし（`top: 78%`）、数値サイズも小さめにする。
  針は三角形＋ハブ（軸）付きで、`針を表示` のチェックに関係なく常に表示する。
- **色が切り替わる位置（帯の境界）に数値を表示**する `showBoundaryValues`（既定 ON）。
  弧の外側に放射状に配置し、ラベル同士が近すぎる場合は弧長ベースで自動的に間引く。
  両端（最小/最大）に重なる境界は最小値・最大値ラベルとの衝突を避けて省略する。

#### 修正

- **最小値・最大値のラベルが見切れていた問題を修正**。ラベルぶんの余白を半径計算に含め、
  端点の角度に応じて `text-anchor` と `dy` を変えて弧の外側へ放射方向に逃がすようにした。
- **単位を入力すると数値が左にずれる問題を修正**。数値と単位を1つの flex 行に並べていたため、
  単位の幅のぶん数値の中心がずれていた。単位を `position: absolute` で数値の右へ逃がし、
  **数値の位置を中央に固定**した。
- **サブ情報を「下」にしたとき、ラベルと数値が左右の端に離れすぎる問題を修正**。
  下パネルでは各行を中央寄せ（`justify-content: center`）にし、スロット自体も中央揃えにした。
  右／左パネルでは従来どおり両端配置のまま。

#### 削除

- **ゲージとサブ情報パネルの間の仕切り線を削除**。

#### 未対応（実機検証待ち）

- 「サブ指標に出す統計」は現状 `editor.arrayOfStrings`（チップ入力）のまま。
  複数チェックボックス UI（`editor.columnMultiSelectionByFieldNameEditor`）は**選択肢を
  `editorProps` で渡す仕組みが無く、ホストがデータソースのフィールド名から一覧を作る**型のため、
  任意の選択肢（合計 / 平均 / 最大）を出せるかは未検証。
  検証手順を `visualizations/editor-probe/ROUNDS.md` の **ROUND 12** に追加済み。
  結果に応じて、この型へ移行するか `editor.checkbox` × 7 に変更する。

#### その他

- ローカル検証を 78 → **99 項目**に拡充（タコメーター・境界ラベル・端ラベルの位置・
  単位の絶対配置・仕切り線の不在・下パネルの中央寄せを検証）。
