# Severity Table
![表示例](examples/example.png)

Splunk Dashboard Studio 向けのカスタムビジュアライゼーション（重要度色分けテーブル）。

サーチ結果をテーブルとして表示し、深刻度の列を値に応じて色分け・並べ替えする。
セキュリティイベント一覧やアラート一覧などを、重要度が直感的に読めるテーブルで可視化する。

## 設計方針：判定ルールをコードに埋め込まない

**v2.0.0 で、深刻度の判定にまつわる暗黙のルールをすべて編集画面のオプションに出した。**

v1 系は「`critical` は `high` より重大」「`warning` は `medium` 扱い」「データに出てくる
深刻度の種類数に応じて色を比例配分する」といったルールを viz のコード側に持っていた。
一見よく気の利いた挙動だが、**設定画面のどこにも書いていないため、なぜその色・その順序に
なったのかをユーザーが確かめられない**（例：同じ `high` でも、データに何種類の深刻度が
含まれるかによって色が変わっていた）。

v2 では次のとおり：

- **深刻度の順位と別名は「深刻度の順位」オプションが決める。** 上ほど重大。
  同じ段階に畳む別名は `|` で区切る。コード側にエイリアス表は無い。
- **色は「深刻度の色」パレットが決める。順位の i 番目 → パレットの i 番目。**
  データの中身では変わらない。`critical` はいつ見ても同じ色。
- **順位一覧に無い値の扱い（並び順・色）もオプション。**
- **数値の範囲外の値の扱いもオプション。**
- **自動判定に使う列名もオプション。**
- **アイコンを付ける対象・サマリのラベルの出し方もオプション。**

コードに残っている深刻度の知識は「オプションの既定値」だけで、すべて上書きできる。

## 特徴

- **データドリブン描画**：サーチ結果の全列をテーブル表示
- **段階数が固定されていない**：3 段階でも 7 段階でも、`P1`/`P2`/`P3` でも `緊急`/`注意` でもよい
- **文字列モード**：順位一覧（`severityOrder`）＋パレット（`severityColors`）で色と順序が決まる
- **数値モード**：値の範囲と色（`severityBands`、`editor.threshold`）で直接判定する。
  上限・下限のない開区間も作れる
- **並び順は 3 択**：サーチ結果のまま / 重大 → 軽微 / 軽微 → 重大（安定ソート）
- **一覧にない値**：最上位/最下位に置く・色を付けるかどうか・その色を選べる
- **件数サマリ**：出現した深刻度をそのまま集計表示（段階数固定ではない）
- **最大表示行数**：大量の結果でも上限を設けて安定描画（0 で無制限）
- **表示スタイル**：セルの形（ピル/ドット/文字/縦線）・行頭カラーバー・縞模様・
  コンパクト表示・タイトル・列の自動省略を切替
- **ライト / ダークテーマ対応**（`useTheme` によるガード付き）
- 外部通信なし。マルチバリューセル・カラム形式データ・空データにガード付き

## データ仕様

- サーチ結果の**全フィールドをそのまま列**として表示する。
- 深刻度の列は「深刻度フィールド」で明示指定する。空欄のときだけ「自動判定に使う列名」
  （既定：`severity` / `sev` / `priority` / `urgency` / `level` / `risk`）に
  一致する列を探し、**先に書かれた名前ほど優先**する。
- 深刻度の型（文字列 / 数値）は**明示オプション**。自動では切り替わらない。

### 文字列モードの色と順位

「深刻度の順位」は 1 行 = 1 段階のリスト。**上ほど重大**。
同じ段階に畳みたい別名は `|` で区切り、**先頭の語がその段階の代表値**になる。

```
critical|crit|fatal|emergency|severe     ← 順位 0（最も重大）→ パレットの 1 色目
high|error|major                         ← 順位 1          → パレットの 2 色目
medium|warning|warn|moderate             ← 順位 2          → パレットの 3 色目
low|minor|notice                         ← 順位 3          → パレットの 4 色目
info|informational|information|debug|ok|normal  ← 順位 4   → パレットの 5 色目
```

- 照合は**大文字小文字を無視した完全一致**（前後の空白は無視）。部分一致はしない。
- 同じ値を複数の段階に書いた場合は、**先に書かれた（より重大な）段階**を採用する。
- パレットが順位より短い場合は**先頭から繰り返す**。
- 上の既定リストは単なる初期値。まるごと `P1` / `P2` / `P3` に置き換えてよい。

### 数値モードの色と順位

「値の範囲と色」（`editor.threshold`）で直接判定する。範囲は `[開始, 終了)` の半開区間、
**最大の範囲の上端だけ閉区間**として扱う（`0–1` / `1–2` … `4–5` なら `5` は最上位）。
範囲が重なる場合は**より高い範囲**を優先する。件数サマリのラベルは範囲表記
（`3–4`、`≧ 90`、`< 10` など）になる。

どの範囲にも入らない値の扱いは「どの範囲にも入らない値」で選ぶ：

| 設定 | 挙動 |
| --- | --- |
| 最も近い範囲の色にする（既定） | 下限未満は最下位バンド、上限超は最上位バンドへ丸める |
| 「一覧にない値」として扱う | 下記の「一覧にない値」の設定に従う |

数値モードで数値として読めない値（`N/A` など）も「一覧にない値」として扱われる。

### 一覧にない値

順位一覧にも範囲にも当たらなかった値。**捨てずに必ず表示する**。

- 並べ替えでの位置：最下位（軽微側）／最上位（重大側）
- 色を付ける：ON なら「一覧にない値の色」で塗る。OFF ならプレーンテキスト
- 同じ順位のもの同士はサーチ結果の順序（初出順）で安定する

深刻度の**値が空**の行は「深刻度が無い行」として扱い、並び順の設定にかかわらず**常に末尾**に置く。

## 開発

```bash
yarn install
yarn build          # dist/<viz>/visualization.js を生成
yarn package        # dist/*.spl（Splunk アプリパッケージ）を生成
yarn verify         # happy-dom で実機なしにバンドルを検証
```

本番向け（minify・ソースマップ無し）は `yarn build:prod` の後に `yarn package` を実行する。
アプリのメタデータは `package/app/app.conf` に格納されている（`package.json` は Node/npm 用）。

## デプロイ（再インストール・再起動なし）

1. `npm version patch --no-git-tag-version && yarn build:prod && yarn package` でバージョンを上げて `.spl` を生成
2. Splunk Web「Install app from file」で **"Upgrade app"（上書き）にチェック**して `.spl` をアップロード
3. ブラウザで `https://<host>:8000/en-US/_bump` を開き **Bump version**（Splunk 再起動の代替）
4. ブラウザをハードリロード（Ctrl+Shift+R）

## サンプル SPL

### 文字列の深刻度（セキュリティアラート一覧）

Splunk 9.0+ の `makeresults format=csv` を使う確実な形式：

```spl
| makeresults format=csv data="_time_str,severity,event,host
2026-07-19 10:12:03,critical,Brute force detected,host-01
2026-07-19 10:09:44,high,Port scan,host-07
2026-07-19 10:05:12,medium,Policy violation,host-22
2026-07-19 09:58:31,low,Login success,host-03
2026-07-19 09:51:20,info,Config reload,host-11
2026-07-19 09:40:07,warning,Unusual outbound traffic,host-05"
```

既定の順位一覧のままで、`warning` は `medium` の段に畳まれる。
畳みたくなければ「深刻度の順位」から `|warning` を消し、独立した段として書き足す。

### 数値の深刻度（urgency 1〜5）

「深刻度の型」を **数値** にして使う：

```spl
| makeresults format=csv data="urgency,event,host
5,Data exfiltration attempt,host-14
4,Malware detected,host-02
3,Repeated auth failures,host-08
2,Suspicious login,host-21
1,Informational log,host-33"
```

### 独自の深刻度体系（P1 / P2 / P3）

「深刻度の順位」を `P1` / `P2` / `P3` の 3 行に置き換えて使う：

```spl
| makeresults format=csv data="ticket,severity,event,host
INC-1001,P1,Cluster down,host-01
INC-1002,P2,Disk pressure,host-04
INC-1003,P3,Cert expiring soon,host-09
INC-1004,P1,Second outage,host-02"
```

### 日本語の深刻度

「深刻度の順位」を `緊急` / `警告` / `注意` / `情報` に置き換える：

```spl
| makeresults format=csv data="発生時刻,深刻度,内容,ホスト
2026-07-19 10:12,緊急,総当たり攻撃を検知,host-01
2026-07-19 10:09,警告,ポートスキャン,host-07
2026-07-19 09:58,注意,ポリシー違反,host-22
2026-07-19 09:51,情報,設定リロード,host-11"
| rename 深刻度 as severity
```

（列名が `severity` 等でない場合は「深刻度フィールド」で明示指定するか、
「自動判定に使う列名」に列名を足す。）

### 旧環境（makeresults format=csv が使えない場合）

```spl
| makeresults
| eval raw=split("critical|Brute force|host-01;high|Port scan|host-07;low|Login success|host-03", ";")
| mvexpand raw
| eval severity=mvindex(split(raw,"|"),0),
       event=mvindex(split(raw,"|"),1),
       host=mvindex(split(raw,"|"),2)
| table severity event host
```

### [2.0.0] - 2026-08-07

**暗黙の自動判定ロジックを廃止し、すべて編集画面のオプションにした破壊的変更。**
v1 系は深刻度の順位・別名・色の割り当てを viz のコード側に持っており、設定画面から
その仕様が読み取れなかった（＝ブラックボックスだった）。v2 ではコードに残る深刻度の
知識は「オプションの既定値」だけになり、すべてユーザーが上書きできる。

#### 追加

- **「深刻度の順位」（`severityOrder`、`editor.arrayOfStrings`）**。1 行 = 1 段階で
  上ほど重大。同じ段階に畳む別名は `|` 区切り（`medium|warning|warn`）。
  **コードに埋め込まれていたエイリアス表（`crit`→`critical`、`warning`→`medium` 等）は
  このオプションの既定値になった**ので、内容を確認・変更できる。
- **「深刻度の色」（`severityColors`、`editor.seriesColors`）**。順位一覧の i 番目の
  深刻度に、パレットの i 番目の色を割り当てる。足りない分は先頭から繰り返す。
- **「自動判定に使う列名」（`severityFieldCandidates`）**。`severity`/`sev`/`priority`/
  `urgency`/`level`/`risk` というハードコードの候補リストをオプション化した（上ほど優先）。
- **「一覧にない値」セクション**：並べ替えでの位置（`unknownOrder`）／色を付けるか
  （`colorUnknown`）／その色（`unknownColor`）。従来は暗黙にグレー無しの比例配分色で
  既知の後ろに置かれていた。
- **「どの範囲にも入らない値」（`bandOutOfRange`）**。数値モードで範囲外の値を
  「最も近い範囲の色に丸める」（従来の暗黙挙動）か「一覧にない値として扱う」かを選べる。
- **「行の並び順」（`sortMode`）に 3 択**：サーチ結果のまま / 重大→軽微 / 軽微→重大。
  従来は ON/OFF のみで、昇順は選べなかった。
- **「深刻度セルの形」（`cellStyle`）を編集画面に露出**。実装はあったのに
  editorConfig に無く、**設定画面から変更できない隠しオプションだった**。
- **「タイトル」（`title`）を編集画面に露出**。同じく隠しオプションだった。
- **「幅が狭いときに列を自動で省略する」（`autoHideColumns`）**。パネル幅が狭いときに
  列を自動で省略する挙動を OFF にできる（従来は常時 ON で説明もなかった）。
- **「アイコンを付ける深刻度」（`topIcon`）**。従来は「データ内で最も重大な値」に
  暗黙に付いていた。順位一覧の1行目に固定／付けない、も選べる。
- **「件数サマリのラベル」（`summaryLabelMode`）**。順位一覧の代表値でまとめるか、
  データの値をそのまま出すか。

#### 変更

- **同じ深刻度の色が、データの中身によって変わらなくなった。** v1 系の文字列パスは
  「データに出現した深刻度の種類数」と「バンド数」を比例配分して色を割り当てていたため、
  **同じ `high` でもサーチ結果によって色が変わる**という分かりにくい挙動だった。
  v2 は「順位一覧の位置 → パレットの位置」の固定対応になる。
- **文字列モードの色は `severityColors`、数値モードの色は `severityBands`** と役割を分けた。
  v1.2.0 では文字列の色も `severityBands` から間接的に取っていた（範囲の値と文字列の
  深刻度に関係が無いのに、範囲設定が文字列の色を左右していた）。
- **深刻度の型は明示オプション（`severityMode`）**。`numericSeverity` チェックボックスを
  「文字列 / 数値」のラジオに置き換えた。
- **件数サマリの日本語ラベル（重大/高/中/低/情報）を廃止**した。コード側の暗黙の
  対応表だったため。サマリには順位一覧の代表値、またはデータの値そのものが出る。
- **既定のタイトル文字列 `Recent High Severity Alerts` を廃止**した。コードに
  埋め込まれた英語のタイトルが、設定していないのに表示されていた。タイトルは
  `title` に入力したときだけ出る（空欄なら非表示。行数を制限して省略が起きている
  ときだけ「3 / 7」の件数表示のために行が出る）。
- 深刻度の値が空の行は、並び順の設定にかかわらず常に末尾に置くようにした（明示化）。

#### 削除

- `sortBySeverity`（→ `sortMode`）、`numericSeverity`（→ `severityMode`）、
  `showTitle`（→ `title` が空欄かどうかで決まる）。

#### 移行について

- **⚠ 既存ダッシュボードの設定は既定値に戻る。設定し直しが必要。**
  旧キーからの読み替えは**意図的に実装していない**。ホストは「既定値と同じ値」を
  options に載せないため、旧キーへフォールバックすると「既定値を選んだときだけ
  元に戻らない」という分かりにくい不具合になるため。
- 既定値は v1 系の既定の見た目（5 段階・同じ配色）を再現しているので、
  **既定のまま使っていた場合、タイトルとサマリのラベル以外の表示は変わらない**。

### [1.2.0] - 2026-07-25

#### 変更

- **深刻度→色の対応を完全にユーザー定義にした。** 従来は `critical` / `high` / `medium` /
  `low` / `info` の **5 段階に固定**され、その 5 色だけが設定できた。深刻度の段階数が
  5 でない環境や、`P1` / `P2` / `P3`・`緊急` / `注意` のような独自の値を使う環境では
  表現できなかった。この固定を撤廃し、**「値の範囲と色」（`severityBands`、`editor.threshold`）
  ただ一つが色を決める**ようにした。編集画面の「＋」で段階を自由に増減できる。
- **数値の深刻度：当たったバンドの色をそのまま使う**ようになった。従来は一度
  「重大／高／中／低／情報」という固定レベル名を経由してから 5 色のどれかに割り当てていたが、
  この中間層を削除した。件数サマリのラベルは範囲表記（`3–4`、`≧ 90` など）になる。
- **文字列の深刻度：ランク順にバンド色を割り当てる**方式にした。データに実際に出現する
  深刻度を重複なく集め、重大な順（既知のエイリアスは `critical` > `high` > … の順、
  未知の値は既知の後ろに初出順）に並べ、バンド色を高い範囲から順に対応させる。
  段階数とバンド数が食い違っても比例配分で必ず色が付く。
  → **`P1` / `P2` / `P3` のような独自の深刻度でも、コードを触らずに異なる色が付く。**
- **エイリアス吸収（`crit`→`critical`、`warn`→`medium` 等）は維持**した。
  色の固定を外しただけで、ソート順と色の割り当て順にはこの知識を引き続き使う。
- **件数サマリが 5 レベル固定でなくなった。** データに出現した深刻度をそのまま
  チップとして表示する。既知の 5 レベルは日本語ラベル（重大/高/中/低/情報）、
  **未知の値は生の文字列をそのまま表示**する。
- 深刻度セルの警告アイコンは「そのデータ内で最も重大な深刻度」に付くようになった
  （従来は `critical` という名前に固定されていた）。
- **`optionsSchema` の `severityBands` を開区間対応の形に修正**した。`openRanges: true` を
  使っているのに `from` / `to` が `"type": "number"` かつ `required` だったため、
  上限・下限なしの範囲（`null`）を作るとダッシュボードの**保存時バリデーションが失敗**していた。
  `{"type": ["number", "null"]}` にし、`required` を `["value"]` のみに変更した。
- 既定の `severityBands` は従来の 5 段階の見た目をそのまま再現するため、
  **既定のまま使っていた場合の表示は変わらない**。

#### 削除

- **固定 5 レベルの色オプションを削除**した：`criticalColor` / `highColor` /
  `mediumColor` / `lowColor` / `infoColor`。editorConfig の「深刻度の色」セクションから
  5 つの `editor.color` を除去し、同セクションを `severityBands` 中心に再構成した。
  `optionsSchema` の 5 キーも削除。
- 内部の `levelColor()`（レベル名→固定色）と `bandsToLevels()` の色一致による
  レベル名逆引きを削除。これが 5 段階固定の原因だった。

- **⚠ 既存ダッシュボードで設定していた深刻度の色は既定バンドに戻る。設定し直しが必要。**
  旧キー（`criticalColor` 等）からの読み替えは**意図的に実装していない**。
  ホストは「既定値と同じ値」を options に載せないため、旧キーへフォールバックすると
  「既定値を選んだときだけ元に戻らない」という分かりにくい不具合になるため。

### [1.1.0] - 2026-07-25

  ホストは「既定値と同じ値」を options に載せないため、旧キーへフォールバックすると

  件数サマリのレベル名は、バンドの色が名前付き 5 色と一致すればそのレベル名を、

  `null` の開区間・空配列・配列以外・不正な色を含む要素のいずれでも描画は落ちず、
