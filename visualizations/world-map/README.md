Splunk Dashboard Studio 向けのカスタムビジュアライゼーション（世界地図＋アタックマップ）。

世界地図上に「起点（src）→ 終点（dst）」を弧で描き、弧に沿って光の筋が流れるアニメーションで
流量・イベントの流れを可視化する。**任意の列（ログ種別・ステータス・深刻度など何でもよい）**で
色分けでき、着弾点をホットスポットとして強調表示する。

世界地図データ（`world-atlas`）はビルド時にバンドルされるため、**実行時のインターネット通信は
不要**（本番 Splunk 環境の制約に準拠）。

## 特徴

- データドリブン描画（SPL の結果から起点・終点の弧を自動生成）
- **色分けの基準は任意の列**（ログ種別 / ステータス / プロトコル / 深刻度 …）。深刻度専用ではない
- **色は「カテゴリ名|色」でユーザーが明示指定**（`editor.arrayOfStrings`）。viz が語彙を推測して勝手に色を割り当てることはしない
- 弧に沿って光の筋が流れるアニメーション（速度変更・停止可）
- **編集画面のフィールド選択**（`editor.columnSelector`）で任意の列を緯度経度・色分けカテゴリ等に割り当て可能
- ホットスポットと弧にツールチップ（地点名・カテゴリ・count）
- **凡例クリックで絞り込み**（もう一度押すと解除）
- **ドリルダウン対応**（弧・地点のクリックでトークンを設定し、他パネルと連動）
- **件数に応じた線の太さ**＋**上位 N 件だけ描画**（件数が多いときの視認性・描画負荷対策）
- **近接した地点をまとめる**（画面距離ベースのクラスタリング。ズームすると自然に分離する）
- **凡例に件数を表示**（「表示 420 / 全 600 件」＋カテゴリごとの件数。切り捨てた分が分かる）
- **ホバーで関連する矢印だけを強調**（どこから来てどこへ行くかを追える）
- **地図アプリのような操作**：マウスホイールでズーム、ドラッグで移動、ダブルクリックで初期表示に復帰
- **中心の経度・緯度を指定**して任意の地域を中心に表示（例: 経度 135 で日本中心）
- **ズームすると地名が現れる**（低ズーム＝国名のみ → 拡大につれて主要都市 → 地方都市）
- **地名を日本語で表示できる**（「地名の言語」オプション。国名・都市名とも Natural Earth の
  日本語名データを同梱。サーチ結果由来の `src_name` / `dst_name` は翻訳しない）
- **ズームすると国境が詳細になる**（世界表示は軽量な 110m、ズーム時は 50m 解像度へ自動切替。
  常時 高/低 固定も選べる。ドラッグ・ズーム操作中も詳細度は落ちない）
- **件数（count）のしきい値で色分けするモード**（「色分けモード」で切替。範囲と色は
  編集画面のしきい値エディタで動的に追加・削除できる）
- **カスタムツールチップ**（弧・地点のホバーで即座に表示されカーソルに追従。
  ブラウザ標準の遅いツールチップではない）
- **マップの右下にフロー一覧テーブルを重ねられる**（v2.0.0。表示中のフローを件数順に一覧。
  オーバーレイなので地図は縮まない。行ホバーで弧を強調、行クリックでドリルダウン。
  → [フロー一覧テーブル](#フロー一覧テーブルv200)）
- **矢印の始点・終点に地点名を常時表示**（`src_name` / `dst_name`。重なりは自動で間引き）
- タイトル / 凡例 / カテゴリフィルタの表示切替オプション
- ライト / ダークテーマ対応（`useTheme` によるガード付き）
- パネルサイズに自動フィット（コンテナサイズを監視して再描画）
- 空データ・必須フィールド欠損・型不一致に対するガード処理

## データ仕様（フィールド）

| 種別 | フィールド名（候補） | 説明 |
| --- | --- | --- |
| 必須 | `src_lat` / `src_lon` | 起点の緯度・経度 |
| 必須 | `dst_lat` / `dst_lon` | 終点の緯度・経度 |
| 任意 | 色分けカテゴリ（`category` / `type` / `log_type` / `event_type` / `status` / `protocol` / `severity` / `threat_level` / `level`） | **任意の文字列**。深刻度に限らずログ種別・ステータス等でよい。色は編集画面の「色分け」で明示指定する（→ [色分けの設定](#色分けの設定)） |
| 任意 | `count`（`events` / `total`） | 値。**件数に限らずバイト数・接続数などの量でもよい**（小数可。単位表記は `countLabel` で変更） |
| 任意 | `src_name` / `dst_name` | 起点・終点の表示名（**地図上にラベル表示**＋ツールチップ） |

フィールドの決め方（優先順）:

1. 編集画面「データフィールド」セクションのフィールド選択（任意の列名を割り当て可能）
2. 未選択の場合は上表の候補名で自動判定（大文字小文字を問わない）

### 地点の集約

同じ都市でも IP ジオロケーションの緯度経度はわずかにばらけるため、そのまま描くと
同一地点に大量のホットスポットが重なって読めなくなる。「表示」→**「近接した地点をまとめる半径」**
（既定 `18`px）で、**画面上の距離**が近い地点を1つのマーカーに統合する。

- **画面距離で判定するため、ズームすると同じ設定値でもクラスタが分離する**
  （拡大するほど同じ px がより狭い地理範囲を指すため）。地図アプリのピンクラスタと同じ挙動。
- 統合された地点は count が合算され、ツールチップに**「ほか N 地点」**と内訳が出る
- 代表座標はクラスタ内の **count 加重平均**（件数の多い地点へ寄る）
- 矢印の始点・終点もクラスタ代表点に吸着するため、終端が数十本に割れて潰れない
- **`0` にすると集約しない**。v1.8.2 以前と同じ見た目に戻したい場合はこれを選ぶ

### 件数の表示

「表示する矢印の上限」（`maxArcs`）は count の多い順に N 本だけを描き、**残りは捨てる**。
捨てられた分の存在が画面に出ないと「全体で何件あるのか」が分からなくなるため、
凡例に件数を出せるようにしている（いずれも既定 ON）。

- **「表示 420 / 全 600 件」** … 絞り込みや `maxArcs` で減っているときの表記。
  全件描いているときは「全 600 件」とだけ出る
- **カテゴリごとの件数** … 各凡例行の右端に桁区切りで併記。
  **絞り込みや上限の影響を受けず、常に全件を数える**（絞り込み中に他カテゴリが
  0 になって「データが無い」と誤読されるのを防ぐため）
- **単位はデータに追従する**。count 列があれば値の合計（単位は `countLabel`。既定 `件`、
  `MB` 等の量の単位も可）、無ければ弧の本数（`本`）を数える
- 極小パネル（凡例がコンパクト表示になるサイズ）では地図を覆わないよう自動的に隠れる

### フロー一覧テーブル（v2.0.0）

「テーブル」→**「テーブルを表示」**（`showTable`、既定 OFF）で、
マップの右下に**表示中のフロー一覧**（値の大きい順）を重ねて表示できる。

- **オーバーレイなので地図は縮まない**。凡例・フィルタと同じガラス調の浮きパネルで、
  マップは常にパネル全域へ描画される（テーブルを出しても地図が見切れない）
- **最下部に固定しつつ、右側を約190px空けて配置**。Splunk がパネル右下の角にホバーで
  出すツールバー（虫眼鏡・更新など）と水平方向にずらして共存する（重ならない）。
  幅もコンパクト（パネルの約38%・最低280px）
- **列ヘッダーのクリックでソート**。もう一度クリックで昇順⇔降順が反転する
  （アクティブな列に ▲/▼ を表示。既定は値の大きい順）
- **ヘッダーバーのクリックで折りたたみ**。テーブルの下の地図が見たいときは、
  ワンクリックで「▶ フロー一覧 N 行」のピルに最小化できる（もう一度で展開）。
  **折りたたんだピルは右上（カテゴリフィルタの左隣）へ移動**し、地図の下部を完全に空ける。
  「折りたたんで表示」（`tableCollapsed`）で最初から畳んでおくこともできる
- **高さは内容にフィットする**。行数が少なければ小さくなり（下に余白を作らない）、
  「テーブルの最大高さ」（`tableHeight`、パネル高さに対する%。15〜60、既定 35）を
  超える分はテーブル内スクロールになる
- **マップと同じ絞り込みが効く**。凡例クリックの絞り込み・「描画する矢印の上限」（`maxArcs`）が
  そのまま反映され、地図と食い違う一覧にならない
- 列は「送信元 / 宛先 / カテゴリ / 件数」。**カテゴリ列・件数列はデータに応じて自動で省略**される
  （色分け列が無い／count 列が無い場合）。カテゴリ列の見出しは「色分けの呼び名」（`categoryLabel`）に追従する
- 表示名（`src_name` / `dst_name`）が無い地点は座標（`51.51, -0.13` 形式）で表示する
- **行ホバー**で、その行の送信元に繋がる弧がマップ上で強調される（地点ホバーと同じ動作）
- **行クリック**は弧クリックと同じドリルダウン（`link.click`）を発火する。
  「インタラクション」でトークン設定すれば他パネルと連動できる（`row.src_name.value` など）
- **描画は上位 200 行まで**。切り捨てが起きたときはフッターに
  「上位 200 件を表示（全 N 件）」と明示する（大量データでも重くならない）
- テーブル上のホイール／ドラッグはテーブルのスクロールに使われ、地図のズーム・パンにはならない
- ズーム中に出る右下のリセットボタンは、テーブル表示中は右上（フィルタの下）へ退避する

### 色分けの設定

**この viz は色を推測しない。** 「カテゴリ名|色」で書いたものだけが色の根拠になる。

色分けの基準は深刻度とは限らない（ログ種別・ステータス・プロトコル・部署など何でもよい）ため、
`critical` が `high` より重い、といった**語彙の意味を viz 側で解釈することは一切しない**。
並び順もユーザー指定（`categoryOrder`）に従い、未指定なら検索結果への登場順になる。

編集画面「色分け」→「カテゴリごとの色」に、1行ずつ次の形式で入力する:

```
high|#ff0000
medium|#e6b93c
low|#38a6ff
```

ログ種別で色分けする場合:

```
auth|#00b0ff
firewall|#ff5a2e
dns|#2dd4bf
```

- 区切りは半角の `|`。前後の空白は無視される
- 大文字小文字は区別しない（`HIGH` と `high` は同じカテゴリ）
- 色は `#RRGGBB` / `#RGB` / `#RRGGBBAA` のほか、`red`・`lime`・`navy` 等の基本的な色名も使える
- **書かなかったカテゴリは「上記に無いカテゴリの色」（既定 `#38a6ff`）**で描かれる。
  凡例ではスウォッチが破線で囲まれ、ホバーすると設定方法が表示される
- 解釈できない行（区切りが無い・色が不正）は**黙って無視**される（描画は壊れない）
- 色分け列の値が空の行は `(未分類)` という独立したカテゴリになる

### 件数で色分けする

「色分け」→「色分けモード」を **「件数（count）のしきい値で色分け」** にすると、
カテゴリ列の代わりに **count の値の範囲**で弧・地点を色分けできる
（通信量マップのようにカテゴリ列が無いデータ向け）。

- 範囲と色は「件数のしきい値と色」で設定する。**「＋」で範囲を動的に追加**できる
- 各範囲は**下限以上・上限未満**。上限を空にすると「以上」の開いた範囲になる
- 凡例・フィルタには範囲名（`0〜100` / `100以上` など）がカテゴリと同じように並び、
  クリックでの絞り込みも同様に効く
- どの範囲にも入らない count は `(未分類)` として「上記に無いカテゴリの色」で描かれる
- このモードでは「カテゴリごとの色」「凡例・フィルタの並び順」は使われない

### 絞り込みとドリルダウン

**凡例クリックで絞り込み**：凡例のカテゴリを押すとその弧だけを表示し、
もう一度押すと解除される（右上のフィルタと連動）。選択中の項目は下線＋太字になる。

**ドリルダウン（インタラクション）**：弧・地点をクリックすると、
ダッシュボードの他パネルへトークンを渡せる。使うには編集画面で設定が要る:

1. パネルを選択 → 右パネルの**「インタラクション」**タブを開く
2. 「トークンを設定」などのアクションを追加する
3. 表示モードで弧または地点をクリックする（**編集モードでは動かない**。下記参照）

viz が渡す値:

| イベント | 発火する要素 | 主な payload |
| --- | --- | --- |
| `link.click` | 矢印（弧） | `row.src_name.value` / `row.dst_name.value` / `row.category.value` / `row.count.value` / 緯度経度4種 |
| `point.click` | 起点・終点の地点 | `row.name.value` / `row.category.value` / `row.count.value` / `row.role.value`（`source` or `target`） |

> **注**: トークンが実際に入るかはダッシュボード側のインタラクション定義に依存する
> （viz は「クリックされた事実」を発火するだけで、何をするかはホストが決める）。
> ローカル検証では「要素ごとに正しい payload が登録されているか」までを確認している。

### 地図の操作方法

| 操作 | 動作 |
| --- | --- |
| マウスホイール | カーソル位置を中心にズーム（`1`〜`40` 倍） |
| ドラッグ | 地図を移動（パン） |
| ダブルクリック | 初期表示（オプションで指定した中心・ズーム）に戻す |
| 右下の `×N ⟲` | 同上（ズーム中のみ表示） |

> **注意**: ダッシュボードの**編集モードでは操作できません**。Splunk が編集中にカスタム viz の
> iframe への入力を遮断する仕様のためで、**表示モードでは正常に動作します**。編集中に見え方を
> 決めたい場合は「中心の経度・緯度」「初期ズーム倍率」を右パネルから設定してください。

- **フロー一覧テーブル**（v2.0.0 の目玉機能。編集画面の新セクション「テーブル」）。
  - `showTable`（既定 OFF）: マップの右下に、**表示中のフロー一覧を件数の多い順**で

#### 変更

- **アニメーションの滑らかさを改善**（遠距離の弧がガクついて見える問題への対処）:
  - **固定ステップ方式に変更**: アニメーション時刻を実時間（wall clock）ではなく
    「描画フレームごとに一定量」進める方式にした。実時間追従では描画が遅れた
    フレームで遅れたぶん光が大きく跳び、それがガクつきに見えていた
    （画面上の速度が高い遠距離の弧ほど顕著）。固定ステップでは移動量が
    毎フレーム等しく、負荷が高いときは全体がわずかにゆっくりになるだけで跳ばない。
  - **速度の正規化**: 長い弧ほど光が高速に動くのを抑制。弧の画面長に応じて周期を
    伸ばし（パネル対角の約半分を基準に最大4倍）、画面上の速度を頭打ちにした。
  - **帯の分割数を弧の長さに応じて増加**（16固定 → 16〜72。長い帯が折れ線に見えない）。
  - **描画を最大30fpsに間引き**（描画負荷も半減）。
- **右下オーバーレイと Splunk ホバーツールバーの共存**。パネル右下の角にホバーで出る
  ツールバー（虫眼鏡・更新など）とテーブルが重なって操作できなくなるため:
  - テーブルは**最下部（12px）に固定しつつ右側を約190px空けて**配置し、

  - ズームリセットボタンは**常に右上（フィルタの下）**に移動し、右下を使わない。
- **編集画面のチェックボックスのラベルを短縮**。長いラベルが編集パネル上で
  折り返されず文字が重なって読めなくなるため、説明的な補足を削って簡潔にした
  （例:「マップの右下にテーブルを表示（表示中のフローを…）」→「テーブルを表示」）。

#### 修正

- **欠損フィールドのエラーメッセージが、実際に見つからなかった列だけを列挙する**ように修正。

#### 修正

- **近接した地点がほとんど集約されていなかった**問題を修正した。
  v1.8.2 までの集約は「投影後の座標を小数1桁で丸めたキーの完全一致」だったため、

### [1.3.0] - 2026-07-25

#### 変更

- **Severity の色設定を「1本の順序付きパレット」に統合した**（`editor.seriesColors` の `severityColors`）。
  従来は「High / Medium / Low という固定名に紐づく専用色3つ ＋ それ以外を受け止める無名の予備パレット」という構成で、
  **`high` / `medium` / `low` に完全一致する語彙を使っている場合しか名前付きの色が当たらない**という制約があった。
  `P1`/`P2`/`P3`、`緊急`/`警告`、`tier1`/`tier2` のような独自の語彙を使うデータでは、
  すべての Severity が予備パレット送りになり、意味づけができなかった。
- 新方式では、サーチ結果に登場した Severity を **凡例の並び順**（既知順 `critical`→`high`→`medium`→`low` を先頭に、
  残りは登場順）に並べ、その順に `severityColors` パレットを上から1色ずつ配る。
  **どんな語彙でも全カテゴリに別々の色が付き、ユーザーが各色を自由に指定できる**。
  カテゴリ数がパレットの色数より多い場合は循環する。
- 既定パレット（`#ff5a2e` / `#e6b93c` / `#38a6ff` / `#b17aff` / `#2dd4bf` / `#ff7ab8` / `#9aa7b8`）は、
  よくある `high` / `medium` / `low` の語彙のとき **v1.2.0 とほぼ同じ見た目**になるよう並べてある。
- **`editor.threshold` は採用していない**。この viz の Severity は文字列カテゴリであり、
  `editor.threshold` が扱う数値レンジには原理的に対応しないため。数値レンジではなく順序付きパレットが正しい型。
- 深刻度フィルタ・凡例・弧／ホットスポットの描画は、任意個・任意名の Severity に対して従来どおり動作する。

  **既定値が options に載らないホスト挙動のため、旧キーへのフォールバックは意図的に実装していない**
  （実装すると「既定値を選んだときだけ直らない」不具合になる）。
  **既存ダッシュボードで線の色を変更していた場合は既定パレットに戻るので、編集画面の「深刻度の色」で設定し直すこと。**
