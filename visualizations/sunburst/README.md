# Custom Viz Sunburst

![表示例](examples/example.png)


https://github.com/user-attachments/assets/05f4d56c-2ff7-45a2-883e-b86c72a8ad6a


Splunk **Dashboard Studio** 向けのカスタムビジュアライゼーション（React/JSX）。

階層構造を**同心円の輪**で表す放射状チャートです。中心が根、外側へ向かうほど下の階層になり、
扇形の**角度**が値の大きさを表します。

同じ [Treemap](../treemap/) と同じデータを扱えますが、役割が違います。

| | 得意なこと |
| --- | --- |
| **Treemap** | 面積の大小を**比べる**（どこが容量を食っているか） |
| **Sunburst** | 階層の**構造**を見る（どこで枝分かれしているか） |

Sunburst は同じ親から出た子が必ず親の角度範囲に収まるため、**包含関係が一目で分かる**のが強みです。

---

## 特徴

- **角度が値に比例** — 扇形の角度がそのまま構成比。子は親の角度範囲を過不足なく埋めるため、
  「この枝は全体の何割で、その内訳はどうか」を同時に読めます。
- **階層の深さは無制限（最大16）** — サーチが返すラベル列の数だけ自動で階層を積みます。
  「一度に表示する輪の数」（`maxDepth`、既定3）は**見た目の密度を決めるだけ**で、
  データの深さは制限しません。輪の上限に当たった枝もクリックすればさらに掘り下げられるので、
  **何階層でも辿っていけます**（編集画面で明示選択できるフィールドは4つまで。
  それを超える階層は自動判定で拾います）。
- **クリックで掘り下げ** — 扇形をクリックするとその枝が中心になり拡大。
  **中央の KPI をクリックすると1つ戻る**（パンくずでも任意の階層へ戻れます）。
  掘り下げ位置は `drillPath` オプションに保存され、編集→保存で永続化できます。
- **中央に合計 KPI** — 表示中の範囲の合計と、その階層名を中央に表示。掘り下げると追従します。
- **細い扇形の自動集約** — サンバーストは扇形が細くなるとクリックもホバーもできなくなるため、
  一定角度（既定 0.3%）未満は「その他（N件）」にまとめます。これが実用上いちばん効きます。
- **色は第1階層で決まり、外側の輪ほど淡く** — 掘り下げても枝の色が変わらないので迷いません。
  パレットは色覚特性（第2色覚）に配慮した8色。
- **ホバーで系統を浮かび上がらせる** — カーソルを乗せた扇形の**祖先（中心側の経路）＋自分＋子孫**を
  明るく残し、無関係な枝を暗くします。根からその枝までの道筋が1本の帯として見えるので、
  どこを掘り下げるか決めやすくなります。オプションで無効化も可能。
- **ホバーでツールチップ** — 階層のパス・値・全体比・内訳件数をカード表示。パネル端では折り返します。
- **負の値は除外** — 角度では負を表現できないため、落としたうえで件数を注記に出します（黙って消さない）。
- **オートフィット** — `ResizeObserver` でコンテナ実寸を測り、常に円が収まる大きさで描画。
- ライト／ダーク両テーマ対応、完全オフライン（外部通信なし）。

## データ仕様

| 役割 | 必須 | 説明 |
| --- | --- | --- |
| 第1階層 | **必須** | 最も内側の輪（index / department など）。 |
| 第2階層以降 | 任意 | 外側へ向かって順に配置されます。**列がある分だけ深くなります**（最大16）。 |
| 値（角度） | **必須** | 正の数値。同じ組み合わせの行は合算されます。 |

> 編集画面で明示的に選べる階層フィールドは第1〜第4までですが、
> 何も選ばなければ**サーチが返した非数値列をすべて階層として使う**ため、
> 5階層以上でもそのまま描画・掘り下げできます。

### 列の自動判定

編集画面でフィールドを選択しなかった場合、以下の順で自動判定します（明示選択が常に優先）。

- **値（角度）** … 一番右の数値列（`stats` の集計列は末尾に来るため。`_` 始まりは除外）
- **階層** … 値列以外の非数値列を左から順に最大4つ

`| stats count by index, sourcetype` のような素直な出力なら、そのまま何も設定せずに描画されます。

## サンプル SPL

### 1. 2階層（推奨・最も使う形）

```spl
| makeresults format=csv data="index,sourcetype,count
web,access_combined,4820
web,error_log,1240
web,ssl_access,860
db,mysql_slow,2100
db,mysql_error,540
db,mysql_general,310
security,auth,1680
security,firewall,3200
security,ids_alert,420
app,json_app,1950
app,app_error,280"
| eval count=tonumber(count)
| table index sourcetype count
```

### 2. 3階層（`maxDepth` を 3 にすると host まで一度に表示）

```spl
| makeresults format=csv data="index,sourcetype,host,bytes
web,access,web-01,52000000
web,access,web-02,38000000
web,error,web-01,4100000
db,query,db-01,91000000
db,query,db-02,27000000
db,slow,db-01,6400000
security,auth,auth-01,15000000
security,firewall,fw-01,23000000"
| eval bytes=tonumber(bytes)
| table index sourcetype host bytes
```

### 3. 5階層以上（輪は3つまで表示し、クリックで深部へ）

「一度に表示する輪の数」は既定3のままでも、クリックしていけば最深部まで辿れます。

```spl
| makeresults format=csv data="region,site,rack,host,service,v
apac,tokyo,r1,srv-01,api,320
apac,tokyo,r1,srv-02,api,180
apac,tokyo,r2,srv-03,db,240
apac,osaka,r1,srv-04,api,150
emea,london,r1,srv-05,db,410
emea,london,r2,srv-06,cache,120
amer,dallas,r1,srv-07,api,260"
| eval v=tonumber(v)
| table region site rack host service v
```

### 4. 実データでの典型パターン

インデックスごとのイベント件数の内訳:

```spl
index=* | stats count by index, sourcetype
```

組織階層ごとの利用量:

```spl
index=audit | stats count by department, team, user
```

ライセンス消費:

```spl
index=_internal source=*license_usage.log type=Usage
| stats sum(b) as bytes by idx, st
| rename idx as index, st as sourcetype
```

## 編集画面のオプション

| セクション | 項目 | 説明 |
| --- | --- | --- |
| データフィールド | 値（角度）／第1〜第4階層 | 各フィールドの明示選択（未設定は自動判定。5階層以上は自動判定で拾う） |
| 配色 | 色1〜8／外側の輪ほど淡く | 第1階層の並び順に色を割り当て。9件目以降は繰り返し |
| 輪と扇形 | 一度に表示する輪の数／扇形の最大数／最小角度／中心の空き半径／輪の間隔／扇形の間隔／角丸 | 輪の数は見た目の密度のみを決める（掘り下げは無制限）。最小角度未満は「その他」に集約 |
| 表示 | ラベル／系統以外を暗くする／中央の合計／パンくず／凡例／掘り下げ／アニメーション | 「ホバー中、その系統以外を暗くする」は既定オン |
| 中央の見出し（任意） | 中央の見出し | 空欄なら階層名を自動表示 |
| 数値 | 小数点以下の桁数／省略表記 | 既定は省略表記オン（1.5M など） |
| デバッグ | オプションのデバッグ表示 | 解決した列・掘り下げ位置・合計値をダンプ |

## 開発コマンド

```bash
yarn install
yarn build        # dist/custom_viz_sunburst/visualization.js を生成（esbuild）
yarn verify       # happy-dom によるローカル検証（Splunk 実機不要）
yarn package      # dist/*.spl を生成
```

## デプロイ（アンインストール・再起動なし）

1. `npm version <patch|minor> --no-git-tag-version` でバージョンを上げ、`package/app/app.conf` の version も同期。
2. `yarn build && yarn package` で新しい `.spl` を生成。
3. Splunk Web「Install app from file」で **"Upgrade app"（上書き）にチェック**して `.spl` をアップロード。
4. `https://<host>:8000/en-US/_bump` で **Bump version** → ブラウザをハードリロード（Ctrl+Shift+R）。

### [1.2.0] - 2026-07-25

#### 追加

- **ホバー中、その系統以外の扇形を暗くする**（`dimOthers`、既定オン）。
  カーソルを乗せた扇形の**祖先（中心側の経路）＋自分＋子孫**を明るく残し、
  無関係な枝を 25% まで落とす。根からその枝までの道筋が1本の帯として見えるため、
  どこを掘り下げるか判断しやすくなる。
  - 祖先を含めるのがポイント。「自分＋子孫」だけだと、その枝がどこから来たのかが分からない。
  - 集約タイル（その他）は系統を持たないため常に暗くなる。
  - ラベルも扇形と同じ不透明度で連動する（暗い扇形の上に文字だけ浮かないように）。
  - 編集画面のチェックボックスで無効化できる。
- ホバー強調に関する検証を追加（計 95 チェック）。
  祖先・子孫が明るく残り、兄弟とその配下が暗くなること、
  チャートから離れたら全て元に戻ることを実測で検証している。

#### 修正

- 扇形ごとの `onMouseLeave` だけに頼っていたため、**扇形の外（円の余白や中心）へ
  カーソルが抜けたときにホバー状態が残る**ことがあったのを修正。
  SVG からの退出でも解除するようにした（`mouseleave` はバブルせず React のルート委譲に
  届かないため `mouseout` も併用）。

#### 生成物

- `dist/custom_viz_sunburst-1.2.0-83de45d.spl`

### [1.1.0] - 2026-07-25

#### 修正

- **扇形の内側の角がえぐれて、隙間が空いたように見えていた**のを修正。
  角丸の描画で「半径方向に c ずらした点」と「角度方向に c ずらした点」を直線で結んでおり、
  隅がえぐられていた（半径と弧長という単位の違うオフセットを混ぜていた）。
  角丸の経路を組み直し、各隅で半径方向・角度方向のオフセットを二次ベジェで正しく結ぶようにした。
  実測で、同じ輪の扇形はすべて厚みが一致するようになった（ばらつき 0.00px）。
  角丸を輪の厚みより大きく指定しても破綻しない。

#### 変更

- **階層の深さの上限を撤廃**（最大16まで）。従来は4階層で頭打ちだったため、
  5階層以上のサーチ結果は深い部分に到達できなかった。
  - 「表示する階層数」を「**一度に表示する輪の数**」に意味を変更した。
    これは見た目の密度を決めるだけで、**データの深さは制限しない**。
    掘り下げ位置からの相対でカウントするため、クリックしていけば何階層でも辿れる。
  - 輪の上限に当たっただけの枝を「葉」と誤判定していたのを修正。
    実際に子を持つかどうかで判定するようにしたので、最外周の扇形もクリックで掘り下げられる。
  - 編集画面で明示選択できるフィールドは従来どおり第1〜第4だが、
    未設定なら非数値列をすべて階層として使うため、5階層以上もそのまま描画できる。

#### 追加

- 角丸のえぐれ検出と、深い階層の掘り下げに関する検証を追加（計 83 チェック）。
  同じ輪の扇形の厚みが一致すること、6階層データを5段掘り下げられることを実測で検証している。

#### 生成物

- `dist/custom_viz_sunburst-1.1.0-83de45d.spl`

### [1.0.0] - 2026-07-25

#### 追加

- 新規作成（初回リリース）。
- 階層構造を同心円の輪で表す放射状チャート。1〜4 階層に対応し、
  サーチが返すラベル列の数から自動で組み立てる。
- **角度＝値の比例配分**。子は親の角度範囲を過不足なく埋めるため、包含関係が視覚的に保証される。

  存在しない枝を指していた場合は全体表示へフォールバックする。

- **細い扇形の自動集約**（既定 0.3% 未満）。サンバーストは扇形が細いとクリックもホバーも

- ホバー時のツールチップ（階層のパス・値・全体比・表示範囲比・内訳件数）。パネル端で折り返す。

- 負の値・非数値の行を除外し、件数を注記に表示。
- 中心の空き半径・輪の間隔・扇形の間隔・角丸をオプション化。
- 中心から外へ広がるアニメーション。
- `ResizeObserver` によるオートフィット、ライト／ダーク両テーマ対応、デバッグオーバーレイ。
- happy-dom によるローカル検証 `yarn verify`（69 チェック）。
  **角度が値に比例すること**（web:db≈2、db:sec≈3、合計が全周）、
  **子の角度幅の合計が親と一致すること**（包含関係）、
  **輪が階層ごとに外へ広がること**を、SVG パスの実測値で検証している。
