# Custom Viz Tab Selector

Splunk Dashboard Studio 用のカスタムビジュアライゼーション拡張。
**クリックでダッシュボードのトークンを切り替えるタブバー**です。

「東京」「大阪」のようなタブを並べ、クリックするとそのタブに対応する値がトークンに入り、
ダッシュボード全体のサーチを切り替えられます。

タブの**数・名前・トークン値はすべて編集UI（右パネル）から設定**できます。

![Tab Selector](examples/example.png)

---

## 特徴

- **タブを自由に増減できる**：編集UIにタブ名を打って Enter で1つずつ増える（上限なし）
- **既定のタブは持たない**：中身はすべて自分で設定する（サンプルの消し忘れが残らない）
- **タブ名も自由**：表示名とトークンに入る値を別々に指定できる（`東京|tokyo`）
- **4種類の見た目**：下線 / 塗りつぶし / ピル（角丸）/ 枠線
- **配置・文字サイズ・色を設定可能**：左/中央/右、幅いっぱいに引き伸ばし、選択色・文字色
- **選択中のタブへインジケータが滑って移動する**（どこへ移ったかが目で追える）
- **サーチ不要**：データソースを紐づけずに配置・設定できるので、
  ダッシュボード上部のナビゲーションとして単体で置ける
- 左右矢印キーでの操作に対応

---

## ⚠ 重要：トークン設定には「インタラクション」の設定が必要

**カスタムビジュアライゼーションは、自分でトークンを書き込むことができません。**
できるのは「タブがクリックされた」という事実をダッシュボードへ通知することだけで、
**それを受けてトークンを設定するのはダッシュボード側の役割**です。

そのため、この viz を置いただけではトークンは変わりません。
**編集画面で「インタラクション」を1回設定する必要があります**（下記セットアップ手順の③）。

これは Splunk 側の仕様であり、標準ビジュアライゼーション（テーブル等）でドリルダウンを
使うときと同じ考え方です。

---

## セットアップ手順

### ① ダッシュボードに Tab Selector を追加する

編集画面 → ビジュアライゼーションを追加 → 「Tab Selector」を選択。

### ② タブを設定する（右パネル「タブ」）

**タブは初期状態では空です。** 追加するまで「タブが設定されていません」と表示されます
（サンプルのタブは埋め込んでいません。消し忘れがダッシュボードに残らないようにするためです）。

「タブ一覧」はテキスト入力欄です。**1タブぶんを入力して Enter** を押すとチップとして確定し、
続けて次のタブを入力できます。**入力した順がそのままタブの並び順**になります。

```
東京|tokyo   ← Enter
大阪|osaka   ← Enter
名古屋|nagoya
```

| 書き方 | 表示されるタブ名 | トークンに入る値 |
|---|---|---|
| `東京\|tokyo` | 東京 | `tokyo` |
| `大阪\|osaka` | 大阪 | `osaka` |
| `本番` | 本番 | `本番`（区切り無しなら表示名がそのまま値になる） |

- 区切り文字は **半角の縦棒 `|`**。**最初の `|` だけ**が区切りなので、
  トークン値の中に `|` が入っていても壊れません（`検索|a|b|c` → 値は `a|b|c`）。
- SPL 側が英字のコードを使う場合でも、タブ名は日本語にできます。
- 前後の空白は自動で除去されます。空のチップは無視されます。

「初期選択タブ」で、最初に選ばれた状態にするタブを 1 始まりの番号で指定します。

### ③ インタラクションでトークンを設定する（ここが必須）

**この設定をしないとタブを押してもトークンは変わりません。**

#### 設定手順

1. 編集画面で **Tab Selector のパネルをクリックして選択**する
2. 右パネルの **「インタラクション」** タブを開く
3. **「+ インタラクションを追加」**（Add interaction）を押す
4. トリガーに **「クリック時」**（On click）を選ぶ
   - ※ カスタム viz が発火できるのは**クリックのみ**です。ホバーや範囲選択は使えません
5. アクションに **「トークンを設定」**（Set tokens）を選ぶ
6. トークンを設定する:

   | 欄 | 入れるもの | 例 |
   |---|---|---|
   | **トークン名** | 自分で決めた名前 | `region` |
   | **設定する値** | `value` を選ぶ | `value` |

7. ダッシュボードを **保存**する

#### 「設定する値」で選べるもの

タブをクリックすると、次の4つが一緒に飛びます。用途に応じて選んでください。

| 選ぶ値 | 入る内容 | `東京\|tokyo` を押した場合 |
|---|---|---|
| **`value`** | **タブのトークン値**（通常はこれ） | `tokyo` |
| `tab` | 同上（`row.tab.value` として届く別名） | `tokyo` |
| `label` | タブの**表示名** | `東京` |
| `index` | タブの位置（1始まり） | `1` |

**`label` の使いどころ**：パネルのタイトルに「$label$ のアクセス状況」と書くと、
サーチには英字コード、画面表示には日本語、という使い分けができます。

#### 複数のトークンを同時に設定する

手順6を繰り返せば、1回のクリックで複数のトークンを設定できます。
たとえば `region` に `value`、`region_name` に `label` を設定しておくと、
サーチと画面表示で別々の値を使えます。

### ④ 各パネルのサーチでトークンを使う

トークンは `$トークン名$` の形で参照します。

```
index=main region=$region$ | timechart count
```

パネルのタイトルにも使えます:

```
$region_name$ のアクセス状況
```

**⚠ 初期状態ではトークンが空**です（タブを1度も押していないため）。
最初から値を入れておきたい場合は、ダッシュボード側の
**「トークンの初期値」**（Default token values）で `region` に既定値を設定してください。

### ⑤ 表示モードで動作確認する

**編集モードではタブをクリックできません。** Studio は編集中、カスタム viz の iframe への
マウス入力を遮断する仕様のためです。動作確認は必ず表示モードで行ってください。

## 設定項目（編集UI）

### タブ

| 項目 | 説明 | 既定値 |
|---|---|---|
| タブ一覧 | `表示名\|トークン値` を入力して Enter で1タブ追加。並び順＝入力順 | （空。自分で設定する） |
| 初期選択タブ | 最初に選択状態にするタブ（1 = 左端） | 1 |

### 表示

| 項目 | 説明 | 既定値 |
|---|---|---|
| タブの形 | 下線 / 塗りつぶし / ピル（角丸）/ 枠線 | 下線 |
| 配置 | 左 / 中央 / 右 | 左 |
| 幅いっぱいに引き伸ばす | タブを均等割りしてパネル幅いっぱいに広げる | OFF |
| 文字サイズ（px） | 8〜48 | 14 |
| トークン値を併記する | タブ名の横にトークン値を小さく表示（設定確認用） | OFF |

### 色

| 項目 | 説明 | 既定値 |
|---|---|---|
| 選択中の色 | 下線・塗りつぶし・枠線に使う色 | `#00A4FD` |
| 選択中の文字色 | 未設定なら自動（塗りつぶし系は白、他は選択色） | 自動 |
| 未選択の文字色 | 未設定ならテーマに合わせた淡色 | 自動 |

## サンプル

### サンプルSPL

この viz 自体はサーチ結果を必要としませんが、**トークンが切り替わることを確認する**ために
別パネルへ次のサーチを置くと分かりやすいです。
（Tab Selector 側のインタラクションでトークン名 `region` を設定しておく）

```
| makeresults format=csv data="region,label,count
tokyo,東京,120
osaka,大阪,86
nagoya,名古屋,54
fukuoka,福岡,41"
| search region="$region$"
| fields label count
```

タブを切り替えると、この表の行が選んだリージョンのものだけに変わります。

タブ設定（右パネル「タブ一覧」に1つずつ入力して Enter）:

```
東京|tokyo
大阪|osaka
名古屋|nagoya
福岡|fukuoka
```

### トークンを使った実際のサーチ例

```
index=web region=$region$ earliest=-24h
| timechart span=1h count by status
```

## データ仕様

このビジュアライゼーションは**サーチ結果を使いません**。
**サーチを紐づけなくても配置・設定できます**（データソースの指定は不要）。
タブの内容はすべて編集UIの設定から作られます。

## 開発

```bash
yarn install
yarn build          # dist/custom_viz_tab_selector/visualization.js を生成
yarn verify         # happy-dom によるローカル検証（Splunk実機不要）
yarn package        # dist/custom_viz_tab_selector-<ver>-<hash>.spl を生成
```

### デプロイ

アンインストール・Splunk 再起動は不要です。

1. `package.json` と `package/app/app.conf` の `version` を上げる
2. `yarn build:prod && yarn package` で `.spl` を生成
3. Splunk Web「Install app from file」で **"Upgrade app"（上書き）にチェック**してアップロード
4. `https://<host>:8000/en-US/_bump` を開き **Bump version**
5. ブラウザをハードリロード（Ctrl+Shift+R）

## 技術メモ

- タブ定義には `editor.arrayOfStrings`（チップ形式のテキスト入力）を使っている。
  viz には `["東京|tokyo", …]` という文字列配列が生で届く。
  - **`editor.threshold` を使わない理由**：threshold でも行を動的に増減できるが、
    value 欄の実体は**カラーピッカー**で、任意の文字列はダッシュボードのソースを
    直接編集しないと入れられない（＝編集UIだけでタブ名を決められない）。
    加えて使わない閾値の数値欄が2つ残り、UI が分かりにくくなる。
  - 旧形式（v1.1.0 以前の `{from,to,value}` オブジェクト）も読めるようにしてあるため、
    既存ダッシュボードは更新してもタブを失わない。
- トークン設定は **`addDrilldownListener` を各タブの DOM ノードに個別登録**して実現している。
  `triggerDrilldown()` は例外を投げずに無視されるため使っていない。
  また、1ノードだけ登録して `payloadCallback` を共有すると「どのタブを押しても同じ値が飛ぶ」
  不具合になるため、**タブごとに専用の payload を閉じ込めている**。
- `config.json` に `events`（`tab.click`）と `supports: ["events"]` の宣言が必要。
  この宣言が無いとホストがイベントを認識せず、クリックしても何も起きない。

### [1.3.0] - 2026-07-26

#### 修正

- **サーチを紐づけなくても配置・設定できるようにした**。`dataContract` の
  `optionalDataSources` に `primary` を挙げていたため、ホストがデータソースの
  指定を求めていた。データ不要の標準 viz（Markdown / RichText / Image）と同じく
  **空**にすることで、サーチなしで設定できる

#### 変更

- **選択中の表示をスライドインジケータに刷新**。タブごとに背景を塗る方式をやめ、
  **1枚のインジケータが選択タブへ滑って移動する**形にした。どのタブからどのタブへ
  移ったかが目で追え、タブ群が連続した1つの部品として見える
- 選択中の文字色を**アクセント色の輝度から自動判定**するようにした。
  従来は白固定だったため、明るいアクセント色（黄など）で文字が読めなくなっていた
- 選択時に文字を太くするのをやめた（幅が変わってインジケータがずれるため）。
  選択は色とインジケータで表す
- 塗り系（塗りつぶし／ピル）の背景に走行レーンを敷き、まとまりを出した
- 余白・角丸・字間を調整し、ホバーは控えめにした（主役をインジケータに集約）
- 空状態にタブ形のプレースホルダを追加し、何が置かれる場所か分かるようにした

#### 追加

- **キーボード操作**：左右矢印キーでタブを移動できる（トークン設定も発火する）。
  フォーカス可能なのは選択中のタブのみ（tablist の作法に沿う）
- パネル幅の変更にインジケータが追従（ResizeObserver）
- 検証項目を追加（インジケータの移動・形ごとの姿・文字色の自動判定）。53 → 66

#### 生成物

- `dist/custom_viz_tab_selector-1.3.0-fbd3f0c.spl`

### [1.2.0] - 2026-07-26

#### 変更

- **タブ定義の editor を `editor.threshold` から `editor.arrayOfStrings` に変更**。
  threshold の value 欄の実体は**カラーピッカー**であり、任意の文字列を入れるには
  ダッシュボードのソースを直接編集する必要があった（＝編集UIだけでタブ名を決められず、
  ラベルとトークン値の使い分けができなかった）。arrayOfStrings はテキスト入力なので
  **編集UIだけで完結する**。あわせて、使わない閾値の数値欄2つが UI から消えた
- タブの並び順は**入力順そのまま**になった（threshold 時代の `from` による並べ替えは廃止）
- `optionsSchema` の `tabs` を文字列配列に変更

#### 追加

- 旧形式（v1.1.0 以前の `{from,to,value}` オブジェクト）の読み取り互換。
  既存ダッシュボードは更新してもタブを失わない

  設定する値の一覧・複数トークンの同時設定・トークン初期値の注意）
- 区切り文字まわりの回帰テスト（ラベルのみ／空値／前後空白／値に `|` を含む場合）と
  新旧形式の互換テストを追加（検証項目 41 → 53）
