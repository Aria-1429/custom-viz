# DPX — DPX

**Splunk 上で動く完全独自のダッシュボード基盤**（アプリ ID: `dpx`）。
Dashboard Studio でも classic（Simple XML）でもなく、独立 React ページの上に自前の
ダッシュボードエンジンを載せたものです。「Splunk 上で動作し、Splunk にサーチが投げられる」
ことだけを前提に、**より映えるダッシュボードを自由に簡単に作れる**ことを目指しています。

実装ナレッジ（構成・スキーマ・viz の作り方・踏んだ罠・E2E ツール）は
[.claude/skills/splunk-viz/references/dpx-platform.md](../../.claude/skills/splunk-viz/references/dpx-platform.md)
に集約しています。**着手前にそちらを読むこと。**

## 構成（30秒版）— v0.2.0 で1ビュー集約（Mako 全廃）

```
Splunk Web
 └ ホストビュー dpx（画面はこの1枚だけ。template="pages/splunk_ui_app.html" ＝ Splunk 同梱）
    └ pages/dpx.js                        ← 唯一のランタイム（ホーム＋ダッシュボード）
        /app/dpx/dpx            → ホーム（一覧）
        /app/dpx/dpx?id=<app>/<name> → ダッシュボード
 └ 定義ビュー（1 ダッシュボード = 1 ビュー XML。isVisible=False の入れ物）
    └ <definition><![CDATA[ DPX スキーマ v1 の JSON ]]></definition>
```

- 保存形式は Studio と同型（ビュー XML に定義 JSON を埋め込む）。REST で動的に作成できる
- **画面間は SPA 遷移（pushState）＝ページ再読込ゼロ**。ボード切替・ホーム往復に白は出ない
- viz は「props を受け取る素の React コンポーネント」を `vizRegistry.js` に登録するだけ
  （iframe なし・config.json なし・splunkd 再起動なし）
- **カスタム Mako テンプレートは不使用**（10.4.0 非推奨・AppInspect 4.4.0 から審査 fail の対象を
  v0.2.0 で全廃）。移行の全経緯と検証は dpx-platform.md §1.1 を参照

## 開発ループ

```bash
cd apps/dpx
rm -rf stage && NODE_OPTIONS=--max-old-space-size=8192 yarn build   # 本番ビルド
yarn package                                                        # dist/*.spl
node ../../tools/dashboard-loop/src/install-viz.mjs $(ls -t dist/*.spl | head -1)
node ../../tools/dashboard-loop/src/shot-page.mjs /en-US/app/dpx/<view> --out /tmp/shots
```

| ファイル | 用途 |
|---|---|
| [`examples/aegis-soc.json`](examples/aegis-soc.json) | **ショーケース**。DPX でしか組めない構図を一枚にまとめたもの（下記） |
| [`examples/all-viz-check.json`](examples/all-viz-check.json) | 全 viz の描画確認用（30枚を並べただけ） |

### AEGIS / Global Threat Operations（ショーケース）

3タブ・25パネル・21データソース・14種の viz。**Studio では組めない**要素を意図的に集めてある:

- **左サイドバータブ**（`tabPosition: "left"`）
- **背景エフェクト**（`constellation`）がパネルの裏で常時動く
- **枠なしパネル**（`frameless`）で見出しと時計を地の上に直接置く
- **全幅の地図を1枚のキャンバスとして使う**（`frameless` + 12列。枠もタイトルバーも無い）
- 自作 viz（world-map / attack-globe / sunburst / sankey-flow / heat-matrix /
  timeline-swimlane / liquid-tube）とネイティブ viz を混在

⚠ **地図（world-map / attack-globe）の上に他のパネルを重ねない。**
DPX は `style.z` でパネルを重ね置きできる（Studio に無い機能）が、
**地図に対して使うと肝心の地形と着弾点が隠れる**。
重ねたガラスパネルは見栄えはするものの、地図の凡例・フロー一覧・
端の国（日本／オーストラリア）が読めなくなった（実機で確認して取りやめ）。
**重ね置きは「地図以外」で使う。** 地図は単独で全幅を与えるのが正解。

投入:

```bash
node tools/dashboard-loop/src/push.mjs apps/dpx/examples/aegis-soc.json --name dpx_aegis
```

⚠ **`makeresults format=csv` の CSV は本物の改行で書く。**
`\n` の2文字を埋め込むと**1行の壊れた CSV**になり、
**HTTP 200 のまま 0 行**が返る（エラーにならないので気づきにくい）。
⚠ **`eval` で日本語のフィールド名を参照するときは `'達成率'` と単引用符で囲む。**
囲まないとこれも **200 で 0 行**になる（このダッシュボードの作成中に実際に踏んだ）。

### [0.10.0] - 2026-08-11

#### 追加

- **⭐ SPL エディタにシンタックスハイライトを追加**（コマンド・関数・文字列が色分けされる）。
  **自前実装ではなく、Splunk 本体のサーチバーが使っている実装をそのまま載せている**:
  - `@splunk/react-search`（**Apache-2.0**）が **Ace エディタ＋`ace/mode/spl`**
    を同梱している。`@splunk/dashboard` の依存として**すでに入っていた**ので追加インストール不要
  - **コマンド一覧は手書きしない。** 実機の Splunk から
    `configs/conf-searchbnf`（Splunk Web のサーチ画面が実際に叩いている REST）を読む。
    手元の環境で **560 スタンザ / うち `*-command` 166 個**。
    → **その環境に入っているコマンド（アプリ独自のものを含む）がそのまま色付く**
  - 実機確認: `timechart` / `eval` / `where` = コマンド色、`by` = 修飾子色、

  パネルとして置く方法はそのまま残しつつ、**パネルを消費せず常に上に出せる**。
  大きさ・秒の有無・日付の有無を設定可能。
  ⚠ **有効なときだけタイマーを回す**（秒なしなら 30 秒間隔）。
  実機確認: 16:12:35 → 16:12:37 と実際に進むことを計測。

#### 修正

- **SPL エディタで行番号と本文が縦にずれていた**のを修正。
  `inputStyle` の `padding` が上下 **0** なのに、行番号側だけ上 6px を入れていたため
  ちょうどその分ずれていた。共有の定数（`PAD_Y`）に統一。

- **テーブルのカラム名に背景色が付いていた**のをやめた（v0.9.0 でスクロール時の
  透け対策として地を敷いたが、色として目立ちすぎた）。
  **地はパネルとまったく同じ色**にして「背景なし」に見せ、
  カラム名であることは**大文字・字間・太さ・下罫線**で示す。罫線も中性色にした
  （並び替え中の列だけアクセント色）。
  ⚠ **透け対策は維持**している。実機確認: ヘッダの計算背景色 `rgb(12,20,36)`＝
  パネル地と同一、かつヘッダ中心の `elementFromPoint` は **TH**（行は透けない）。
- **入力コントロールが平板で安っぽく見えた**のを改善。
  内側のハイライト＋落ち影で奥行きを出し、hover / focus の状態差を付けた。
  フォーカスは**角丸に沿うリング**（`box-shadow`）にした
  （`outline` の矩形が丸角からはみ出していた）。
  ⚠ 影は **animate しない**（毎フレーム再描画になるため）。transition は状態変化のみ。

#### その他

- **`THIRD-PARTY-NOTICES.txt` を追加**（バンドルした `@splunk/react-search` の
  Apache-2.0 条文を同梱）。`.spl` に含まれることを確認済み。

### [0.9.0] - 2026-08-11

#### 修正

- **テーブルをスクロールすると固定ヘッダに行が重なって読めなかった**のを修正。
  原因は `background: 'inherit'` で、親の `<tr>`（透明）を継承して
  **計算値が `rgba(0,0,0,0)` になっていた**（`position: sticky` は効いていて
  「透けていた」だけ）。不透明な地を指定し、`z-index` も明示。
  **合計行（`<tfoot>`）も半透明（0.94）だったので同時に不透明化**。
  実機確認: ヘッダの計算背景色が `rgb(13,21,38)`、ヘッダ中心の
  `elementFromPoint` が `TD` → **`TH`** に変化。
- **棒グラフが大量行でバーごと消えていた**のを修正。
  `flex` + `gap: 8px` の固定間隔だったため、**件数 × 8px が幅を食い尽くし
  バー自身の幅が 0 になっていた**（実機計測: 200 行で **171/171 本が 0px**）。
  間隔を「幅から算出する」方式（スロットの 18%・最大 6px）に変更し、
  バーには最低 1px を必ず残す。実機再計測: 200 行で **6.06px・0px のバーは 0 本**。
- **背景「グリッド」が 1920×1080 で 22fps まで落ちていた**のを修正（**60fps**）。
  `background-position` を animate していたため合成に載らず、
  **毎フレーム全面が再描画（RasterTask）**されていた。`transform` で
  1周期ぶん動かす方式へ変更。⚠ **アニメーション要素 38 個のうち、この 1 個だけで
  fps が決まっていた**（他を全部止めても効果ゼロ。個数ではなくプロパティの問題）。

#### 追加（編集の操作性）

- **編集モードでもパネルを右クリックできるように**（従来は表示モードのみ）。
  複製 / このパネルの設定を開く / データソースを編集 / 最前面へ / 最背面へ /
  タイトルバーの表示切替 / SPL をコピー / 削除。
  右クリックした瞬間に**そのパネルを選択**する（選択せずに「設定を開く」を押すと
  別のパネルの設定が出てしまうため）。削除は赤字＋区切り線で分離。
- **データソースに「保存」ボタン**をヘッダへ追加。未保存のときだけ強調し、
  保存済みなら押せない。ダイアログを閉じてから別途保存する必要をなくした。
- **「削除」を押しにくい位置へ**。「複製」の真横（誤爆しやすい）から、
  下部の「危険な操作」枠へ隔離し、**2段階**（「削除…」→「本当に削除」、
  5秒で自動解除）にした。実機計測: 複製→削除の距離が **512px**。
- **SPL 編集を見やすく**: **行番号**・**整形**（パイプで改行）・**実行**ボタン・
  行数/文字数の表示。**Tab はインデント**として扱う（既定だとフォーカスが飛ぶ）。
  ⚠ 整形は `formatSpl()` として `spl.js` に分離しテスト付き。
  **文字列リテラル内の `|` では改行しない**（`eval x="a|b"` や rex の
  `(?<a>x|y)` を壊さない）。冪等性もテストで担保
  （最初の実装は整形するたびインデントが増えていた）。

#### 修正（編集 UI）

- **パネルから「データソースを編集…」を開くと一覧の先頭が選ばれていた**のを修正。
  そのパネルが参照しているデータソースを選択状態で開き、一覧が長い場合は
  そこまでスクロールする。実機確認: 3番目を参照するパネルから開いて **`C: 対象`** が選択された。
- **ビジュアライゼーション選択画面で文字がはみ出していた**のを修正。
  カスタム viz の type（`custom_viz_attack_globe.custom_viz_attack_globe`）が長く、
  **flex の子が既定で縮まない**（`min-width:auto`）ため隣のカードに重なっていた。
  `minWidth:0` と省略表示を追加。実機計測: **はみ出し 0 件 / 45 カード**。

#### 修正（折れ線）

- **ツールチップがパネルからはみ出していた**のを修正。10 系列で高さ 218px になり、
  パネル下端を **20px 超過**して隣のパネルに重なっていた（実機で計測）。
  収まる行数を高さから逆算して打ち切り、残りは「ほか N 件」と表示。
  **値の大きい順に並べ替える**ので切られるのは常に小さい系列。
  `maxHeight` でも二重に止める（見積もりがズレても絶対に出さない）。
  実機再計測: **はみ出し −23px / −22px / −72px**（すべてパネル内）。
- **X 軸ラベルが全部 `2026-08-1…` になっていた**のを修正。ISO 文字列を
  先頭10文字で切っていたため**時刻の情報が真っ先に消えて全ラベルが同一**に
  なっていた（実機で `allSame: true` のパネルが3枚）。
  標準 viz に倣い `15:00` 形式にし、日付が変わる位置だけ下段に `8/12` を添える。
- **Y 軸の目盛りが半端な値だった**のを修正（14.1k / 10.6k / 7.1k → 5.0k / 10.0k / 15.0k）。
  min〜max を単純に5等分していたため。`niceScale()` で切りのいい刻みにする。
- **凡例が右端で切れていた**のを修正。系列が多いときは**右側に縦積み**にする
  （標準 viz と同じ形）。`legendPos` で 自動 / 右 / 下 を選べる。

#### 追加（折れ線）

- **第2Y軸**（★スケール差の救済）。`splunkd`（3000〜12000）が1本混じるだけで
  他の系列が全部「下の平らな線」になる問題に対して、標準 viz と同じ逃げ道を用意した:
  - 「右軸で描く系列」で明示指定
  - 「桁違いの系列を自動で右軸へ」で自動判定（中央値の10倍以上を右へ）
  - 右軸の系列は凡例に `R` を付けて区別する
- `niceScale()` / `formatAxisLabels()` を `scale.js` に追加し単体テストを追加。
  ⚠ **テストで実害級のバグを検出**: `new Date('srv-web-01')` が
  **2001年1月1日として通ってしまう**ため、ホスト名の軸が「1/1, 2/1, …」に
  化けていた（先頭が `YYYY-MM-DD` かを厳密に見るよう修正）。

#### 追加

- **パネルタイトルの位置と質感を設定できるように**（従来は左上固定）。
  - 位置: 左 / 中央 / 右
  - 質感 10 種: 自動（従来どおり質感に追従）/ 管制ラベル / 素 / 太字 /
    バッジ（先頭に丸）/ 左に色帯 / 地を敷く / リボン / 下線つき / 等幅
  - **既定の「自動」は従来と同じ判定**（`variant === 'noc'`）なので
    既存ダッシュボードの見た目は変わらない
- **ダッシュボードのタイトルも同様に設定できるように**（`style.header`）。
  位置（左/中央/右）・大きさ（14〜48px）・質感 6 種（素 / 左に色帯 / 下線 /
  地を敷く / 発光 / 等幅）・右端の日付スタンプの ON/OFF。
  中央寄せのときは日付を下段へ回す（同じ行だと見出しが中央からずれるため）。
- **棒グラフを標準 viz 準拠に強化**（`splunk.bar` / `splunk.column` の挙動に寄せた）:
  - **値軸と目盛り線**（切りのいい 1/2/2.5/5×10ⁿ 刻み）。
    1 本ずつに数字を出せない密度でも大きさが読める
  - **ラベルの自動間引き**（幅に応じて N 本おき）。全部出して重なる状態を解消
  - **向きを縦／横で選べる**（`splunk.column` / `splunk.bar` 相当）。
    横向きは行の高さを保ったままパネル内スクロール
  - **最大件数（既定 200・0 で無制限）**。切り詰めたときは
    「上位 200 / 500 件」と明示する（黙って隠さない）
  - **60 本を超えたら描画アニメを自動で切る**（登場アニメの合成レイヤが
    残り続けるため。演出より読めることを優先）
- 目盛り計算 `niceTicks()` を `scale.js` へ分離し、`yarn test` に単体テストを追加
  （境界値・0 件・NaN で固まらないこと・目盛りが最大値を覆うこと）。
  **テストで「軸の上端と最上段の目盛りがズレる」バグを検出**（max=99 のとき
  最上段が 75 になり、線の位置と数字が食い違う。目視では気づけない）

### [0.8.0] - 2026-08-11

#### 追加

- **登場アニメを 2 → 6 種に**（ダッシュボード単位）:
  ライズ / フェード / **ズーム** / **スライド（左から）** /
  **フリップ（奥から起き上がる）** / **アンフォールド（縦に開く）**
- **常時アニメを新設**（パネル単位・「見た目の詳細」）:
  **ふわふわ（上下）** / **明滅（呼吸）**。
  ⚠ 編集中と全画面では自動で止める（掴みにくくなる／読むための表示なので）
- **パネル質感を 10 → 14 種に**:
  - **ホログラム** … 斜めの薄い縞＋外周のリムライト
  - **ネオン管** … 枠だけを強く光らせ、中身は暗いままにして数値を立てる
  - **方眼紙** … 16px と 80px の格子を重ねた設計図の意匠
  - **伝票** … 上辺だけミシン目風の点線。一覧を「札」に見せたいとき
- **背景エフェクトを 14 → 17 種に**:
  **回路基板**（格子＋交点のノード）/ **等高線**（同心楕円）/
  **星空**（奥行きの違う3層を別々の速さで流す視差）

#### 性能上の方針

⚠ **すべて「面積に比例する半透明の塗り」を避けて作った**（[viz-performance.md](../../.claude/skills/splunk-viz/references/viz-performance.md) §2）:

- アニメは **transform / opacity だけ**で組む（GPU 合成に載る）。
  `filter` や `box-shadow` を animate すると毎フレーム再描画になり、
  パネル数に比例して重くなる
- 新しい質感に **`backdrop-filter` は使っていない**。
  下のアニメが動くたび再ブラーになるうえ、**文字のサブピクセル AA を無効化**する。
  ホログラム感は「縞1枚＋内側の影」で出している
- 星空の点は 0.5〜1.4px。**塗り面積が増えない**ので層を増やしても軽い

### [0.7.1] - 2026-08-11

#### 追加

- **Studio では DOS（式）を手で書くしかなかった機能を、DPX では UI から設定できるようにした。**
  Studio の DOS は `> table | seriesByName("cpu") | gradient(heat)` のような
  式をソースに直接書く必要があり、**編集画面からは設定できない**（17関数は
  [studio-standard-viz.md](../../.claude/skills/splunk-viz/references/studio-standard-viz.md) §2.3.3 に実機検証済みの一覧がある）。

  | DOS の関数 | DPX での設定場所 |
  |---|---|
  | `rangeValue` | 色のルール → **範囲**（従来から対応） |
  | `matchValue` | 色のルール → **一致**（従来から対応） |
  | **`gradient`** | 色のルール → **グラデーション**（新規） |
  | **`maxContrast`** | 値による色 → **文字色を自動で読みやすく**（新規） |
  | **`divideBy`** | 数値の書式 → **割る数**（新規） |
  | **`prefix`** | 数値の書式 → **接頭辞**（新規。単位＝接尾辞も追加） |

- **グラデーション（`gradient` 相当）** … **しきい値を1つも決めずに**、
  値の最小〜最大を色の並びへ連続で写像する。範囲は自動（データの最小・最大）だが、
  最小・最大を明示することもできる
- **文字色の自動選択（`maxContrast` 相当）** … セルの地の色から
  **白／黒のうちコントラストが高い方**を自動で選ぶ。
  ⚠ 判定は **WCAG の相対輝度**で行う。単純な `(r+g+b)/3` だと緑を暗いと誤判定し、
  緑の地に黒文字を置いてしまう
- **単位換算（`divideBy` 相当）と接頭辞・接尾辞（`prefix` 相当）** …
  **SPL を書き換えずに**見た目だけ整える。`1048576` で割って ` MiB` を付ける等
- 上記の書式は**対象の列を選べる**。⚠ 列を指定できないと
  **CPU まで "0.0 MiB"、ホスト名まで "srv-web-01"** になる（実機で確認して追加）

     `cornerBrackets()` の `backgroundImage` が**色レイヤーごと上書き**していた。

  3. **入力欄が灰色で読みにくい**。`inputStyle` が `rgba(0,0,0,0.28)` を固定で敷いていた。
     → ライト時は白地＋濃いめの枠にする
- ⚠ 1と2は**同じ CSS の落とし穴**（一括 `background` は `background-color` を初期化する／
  `backgroundImage` に潰される）。順序を「一括 → 個別」にするか、最初から個別指定にする
