# DPX — DPX

**Splunk 上で動く完全独自のダッシュボード基盤**（アプリ ID: `dpx`）。
Dashboard Studio でも classic（Simple XML）でもなく、独立 React ページの上に自前の
ダッシュボードエンジンを載せたものです。「Splunk 上で動作し、Splunk にサーチが投げられる」
ことだけを前提に、**より映えるダッシュボードを自由に簡単に作れる**ことを目指しています。

実装ナレッジ（構成・スキーマ・viz の作り方・踏んだ罠・E2E ツール）は
[.claude/skills/splunk-viz/references/dpx-platform.md](../../.claude/skills/splunk-viz/references/dpx-platform.md)
に集約しています。**着手前にそちらを読むこと。**

## 構成（30秒版）— v0.2.0 で1ビュー集約（Mako 全廃）

```
Splunk Web
 └ ホストビュー dpx（画面はこの1枚だけ。template="pages/splunk_ui_app.html" ＝ Splunk 同梱）
    └ pages/dpx.js                        ← 唯一のランタイム（ホーム＋ダッシュボード）
        /app/dpx/dpx            → ホーム（一覧）
        /app/dpx/dpx?id=<app>/<name> → ダッシュボード
 └ 定義ビュー（1 ダッシュボード = 1 ビュー XML。isVisible=False の入れ物）
    └ <definition><![CDATA[ DPX スキーマ v1 の JSON ]]></definition>
```

- 保存形式は Studio と同型（ビュー XML に定義 JSON を埋め込む）。REST で動的に作成できる
- **画面間は SPA 遷移（pushState）＝ページ再読込ゼロ**。ボード切替・ホーム往復に白は出ない
- viz は「props を受け取る素の React コンポーネント」を `vizRegistry.js` に登録するだけ
  （iframe なし・config.json なし・splunkd 再起動なし）
- **カスタム Mako テンプレートは不使用**（10.4.0 非推奨・AppInspect 4.4.0 から審査 fail の対象を
  v0.2.0 で全廃）。移行の全経緯と検証は dpx-platform.md §1.1 を参照

## 開発ループ

```bash
cd apps/dpx
rm -rf stage && NODE_OPTIONS=--max-old-space-size=8192 yarn build   # 本番ビルド
yarn package                                                        # dist/*.spl
node ../../tools/dashboard-loop/src/install-viz.mjs $(ls -t dist/*.spl | head -1)
node ../../tools/dashboard-loop/src/shot-page.mjs /en-US/app/dpx/<view> --out /tmp/shots
```

### AEGIS / Global Threat Operations（ショーケース）

3タブ・25パネル・21データソース・14種の viz。**Studio では組めない**要素を意図的に集めてある:

- **左サイドバータブ**（`tabPosition: "left"`）
- **背景エフェクト**（`constellation`）がパネルの裏で常時動く
- **枠なしパネル**（`frameless`）で見出しと時計を地の上に直接置く
- **全幅の地図を1枚のキャンバスとして使う**（`frameless` + 12列。枠もタイトルバーも無い）
- 自作 viz（world-map / attack-globe / sunburst / sankey-flow / heat-matrix /
  timeline-swimlane / liquid-tube）とネイティブ viz を混在

⚠ **地図（world-map / attack-globe）の上に他のパネルを重ねない。**
DPX は `style.z` でパネルを重ね置きできる（Studio に無い機能）が、
**地図に対して使うと肝心の地形と着弾点が隠れる**。
重ねたガラスパネルは見栄えはするものの、地図の凡例・フロー一覧・
端の国（日本／オーストラリア）が読めなくなった（実機で確認して取りやめ）。
**重ね置きは「地図以外」で使う。** 地図は単独で全幅を与えるのが正解。

投入:

```bash
node tools/dashboard-loop/src/push.mjs apps/dpx/examples/aegis-soc.json --name dpx_aegis
```

⚠ **`makeresults format=csv` の CSV は本物の改行で書く。**
`\n` の2文字を埋め込むと**1行の壊れた CSV**になり、
**HTTP 200 のまま 0 行**が返る（エラーにならないので気づきにくい）。
⚠ **`eval` で日本語のフィールド名を参照するときは `'達成率'` と単引用符で囲む。**
囲まないとこれも **200 で 0 行**になる（このダッシュボードの作成中に実際に踏んだ）。

### [0.5.8] - 2026-08-11

#### 変更

- **色の設定 UI に「実際に適用されている値」を表示するようにした。**

  v0.5.7 では未設定のとき色を隠していたが、それだと
  **「今どの色が効いているのか」が分からない**。
  → 未設定のときは**実効値をスウォッチに塗り、入力欄のプレースホルダにも出す**。
  「未設定」であることは**枠を破線にする**ことで区別する。

  - `themes.js` に **`effectivePanelColor(key, theme, variant)`** を追加。
    **描画と同じ `panelSurface()` から導く**ので、質感を足しても UI が古くならない
    （値を手で書き写すと必ずズレる）
  - 枠線を引かない質感（`noc` など）は「なし（枠線を引かない）」と明示する
  - スウォッチを押すと**その実効値で確定**できる（今の見た目を保ったまま固定できる）

  実機検証（質感3種で UI 表示とパネルの実地の値を突き合わせ）:

  | 質感 | UI の表示 | パネルの実地 | |
  |---|---|---|---|
  | `noc`（既定） | `rgba(10,18,34,0.42)` | `rgba(10,18,34,0.42)` | 一致 |
  | `card` | `rgba(20,30,52,0.85)` | `rgba(20,30,52,0.85)` | 一致 |
  | `outline` | `transparent` | `rgba(0,0,0,0)` | 一致 |

### [0.5.7] - 2026-08-11

#### 修正

- **色の設定 UI が「未設定」を「#4ea1ff が設定済み」のように見せていた**問題を修正。

  `<input type="color">` は**空の値を持てない**ため、未設定でも必ず何かの色が
  表示される。そこにフォールバック色 `#4ea1ff` を渡していたので、
  **新規パネルの「見た目の詳細 → 背景色」が青に設定済みのように見えていた**
  （実際には未指定で、プリセットの色が効いている）。

  - 未設定のときは**ピッカーを出さず、斜線入りのスウォッチ**を出すようにした。
    押すと初めて色が入る（＝そこで初めて実際に適用される）
  - 入力欄のプレースホルダを「（既定）」→**「未設定（プリセットのまま）」**に変更。
    「既定」だと何らかの既定色が入っているようにも読めるため
  - **指定済みのときだけ `×` ボタン**を出し、未設定へ戻せるようにした
    （従来は一度色を入れると未設定に戻す手段が無かった）
  - `ColorInput` に **`allowUnset`** を追加。ダッシュボード全体の
    「アクセント色」「カギ括弧の色」は**常に実効値がある**欄なので `false` にし、
    従来どおり実際に効いている色を表示する

  実機で往復を確認（背景色の欄）:

  | 状態 | ピッカー | 入力欄 | パネルの実地色 |
  |---|---|---|---|
  | 初期 | 未設定表示 | 空 | `rgba(10,18,34,0.42)`（プリセット） |
  | 色を指定 | `#4ea1ff` | `#4ea1ff` | `rgb(78,161,255)`（実際に適用） |
  | `×` で解除 | 未設定表示 | 空 | プリセットへ復帰 |

### [0.4.3] - 2026-08-11

#### 修正

- **パネルの枠（コーナーフレーム）が丸ごと消える**問題を修正。⭐ これが本命の原因。

  `panelStyleOverrides()` が「背景色」を **CSS の `background`（一括）** で書いていた。
  一括プロパティは **`background-image` を `none` にリセットする**ため、
  カギ括弧を描いている `linear-gradient` 8枚が**全部消えていた**。

  → **`backgroundColor`（単独）で書くように変更**。地の色は従来どおり変わり、
  枠は残る。

  発生条件は**「見た目の詳細 → 背景色」に値が入っていること**だけ。
  `transparent` に限らず**普通の色でも同じように消える**。
  「一度透明を解いて再度透明にすると枠が無くなる」のは、解除時に**色**が
  `style.bg` に書き込まれ、それも一括プロパティ経由なので**枠は戻らない**ため。

  実機検証（v0.4.3 適用前→後）:

  | 対象 | 修正前 | 修正後 |
  |---|---|---|
  | `bg=transparent` の noc パネル | 枠 **0層**（消失） | 枠 **8層** |
  | `bg=#1a2740`（色指定） | 枠 **0層**（消失） | 枠 **8層** |
  | `bracketSolid` + `bg=transparent` | 枠 **0層**（消失） | 枠 **8層** |
  | 全 viz 検証ダッシュボード（30枚・全て `bg:transparent`） | 枠あり **0/30** | 枠あり **30/30** |

> **【訂正】** v0.4.1 で「原因はカギ括弧の色の透明化」、v0.4.2 で「原因は SVG 図形の
> 半ストローク欠け」と報告したが、**ユーザーが見ていた「枠が存在しない」現象の原因は
> どちらでもなく、この `background` 一括リセット**だった。
> v0.4.1／v0.4.2 の修正自体は別の実在する不具合への対処なので取り消していない。
> **誤診の原因**：症状を再現せずに「透明」「テーマ切替」という言葉から犯人を推定し、
> **`style.bg` が設定された状態を一度も試していなかった**。
> 症状は**ユーザーの設定を実際に再現してから**切り分けること。

### [0.4.2] - 2026-08-11

#### 修正

- **図形「コーナーフレーム」（`shape.nocFrame`）の枠が切れる**問題を修正。
  **右辺と下辺の腕4本が完全に消えていた**（実機で画素を測って確認。
  8本中4本が背景と同じ輝度）。

  原因は **SVG の線が座標の「中心」に引かれること**。腕を箱の端ちょうど
  （`x=幅` / `y=高さ`）に置いていたため、太さの半分が SVG の外へはみ出し、
  `overflow:hidden` で削られていた。1px 線だと残る 0.5px を
  `shapeRendering="crispEdges"` がピクセル境界に丸めて**完全に消す**。
  左辺・上辺だけ生き残っていたのは、内側の半分が箱に残るため。

  - 腕の座標を**線の太さの半分だけ内側**に寄せ、ストローク全体が箱に収まるようにした
  - `crispEdges` を外した（内寄せをピクセル境界に丸め戻して**再び端に戻してしまう**ため）
  - 太さ 0.5〜4px × 内側余白 0/5/24px の**18通りで全8本が箱の中**に収まることを検証

> **調査メモ**：ユーザーからの「すりガラスにしてコーナーフレームに戻すと復活する」
> という手がかりが決め手になった。パネルの**質感**（`variant='noc'`。CSS の
> `linear-gradient` 8枚で描く方）は正常で、崩れていたのは**同名の別物**＝
> **図形パネル「コーナーフレーム」**（SVG の `<line>` 8本で描く方）だった。
> 質感を切り替えると再マウントが起き、たまたま見え方が変わるため
> 「テーマ／質感のせい」に見えていた。**同じ名前で実装が2つある**のが
> 誤診の温床だったので、上の原因を両者の区別ごと記録しておく。

### [0.4.0] - 2026-08-11

#### 変更（破壊的）

- **サーチはすべてデータソースに集約**。パネルに SPL を直書きする形を廃止した。
  同じサーチが複数パネルに散らばると「どのパネルがどれを使っているか」「直すとき
  何枚直すか」が追えなくなるため、**パネルは必ずデータソースを参照する**
  - インスペクタから「このパネルに直接書く」を削除。サーチ元は
    **データソースの選択**（＋「＋ 新しいデータソースを作る」）だけになった
  - パネルの新規作成時も、既存データソースがあればそれを参照し、
    無ければサンプル SPL のデータソースを自動生成して参照する
  - パネル固有の絞り込みは従来どおり **`postSearch`（後続パイプ）** で行う

#### 追加

- **旧形式の自動移行**（`migrateToDataSources`）。直書き SPL を持つ定義は
  **開くだけでデータソースへ切り出される**。移行時は編集モードで
  「サーチ N 件をデータソースにまとめました」と通知し、保存で確定する
  （開いただけでは未保存扱いにしない）
  - **同じ SPL は 1 つのデータソースに集約**（時間指定が同じものだけ。
    earliest/latest が違うものは別データソースにする）
  - **冪等**：2 回流しても増えない。変更が無ければ同じ参照を返す（無駄な再描画を防ぐ）

#### 検証

- 移行ロジックの単体確認（重複集約・時間違いの分離・既存参照の不変・値の保持・冪等性）
- 実機で旧形式ダッシュボード（直書き3枚／うち2枚は同一 SPL）を開き、
  **通知が出てデータソースが 2 件に集約**され、3 パネルとも正しく描画することを確認
- インスペクタに「直接書く」が出ないこと、データソース選択・後続パイプ・
  「データソースを編集…」が出ることを実機で確認

### [0.3.2] - 2026-08-11

#### 修正

- **ライト系プリセット（ライト／ペーパー）で背景がおかしくなる不具合を修正**。
  原因は独立した3つで、いずれも**実機で計測して特定**した:
  1. **`html/body` が濃紺のまま**。`pages/dpx/bootPaint.js` が白フラッシュ対策で
     `background: #0a1020 !important` を当てており、テーマが変わっても解除されなかった。
     → `useDpxGlobalStyles` がテーマ確定後に上書きするようにし、
     ダッシュボード画面（従来はホームだけが呼んでいた）でも呼ぶようにした
  2. **パネルの地の色が消える**（ライトでもパネルが暗いまま）。`panelSurface` の
     `noc` / `bracketSolid` が `background`（一括）で色を指定した直後に、
     `cornerBrackets()` の `backgroundImage` が**色レイヤーごと上書き**していた。
     → 色は `backgroundColor` で指定するよう変更
  3. **入力欄が灰色で読みにくい**。`inputStyle` が `rgba(0,0,0,0.28)` を固定で敷いていた。
     → ライト時は白地＋濃いめの枠にする
- ⚠ 1と2は**同じ CSS の落とし穴**（一括 `background` は `background-color` を初期化する／
  `backgroundImage` に潰される）。順序を「一括 → 個別」にするか、最初から個別指定にする

#### 検証

- 5プリセット（ライト／ミッドナイト／ペーパー／ネオン／ミッドナイトへ復帰）を
  実機で切り替え、**body の実測輝度**が追随することを確認
  （ライト246・ペーパー239・ダーク系16。プリセット固有の地の色も保持）

#### 配布物

- `dist/dpx-0.3.2-248c467.spl`

### [0.3.1] - 2026-08-11

#### 追加

- **カラーピッカーに「透明」を追加**（`ColorInput`＝インスペクタの全色欄に反映）。
  ネイティブの `<input type="color">` では `transparent` を選べないため専用ボタンを置いた。
  透明中はピッカーを**市松模様のプレビュー**に差し替える
  （そのままだと fallback 色が出て「透明にしたのに色が付いて見える」ため）。
  `transparent` / `none` / α=0 の `rgba()`・8桁 HEX も透明として判定する（`isTransparent`）

#### 修正

- ⚠ **透明を解除できなくなる不具合**（実装中に実機で発見）。
  呼び出し側が `fallback={t.accent}` を渡す箇所があり、その accent は
  `style.accent || preset.accent` で解決されるため、**accent を透明にすると
  fallback も透明**になり、解除ボタンが `transparent` を再設定していた。
  解除の戻り先を常に不透明色にして解消（`safeFallback`）

#### 配布物

- `dist/dpx-0.3.1-248c467.spl`

### [0.3.0] - 2026-08-11

#### 追加

- **既存カスタム viz 30 種を DPX に全面対応**（iframe なしでネイティブにホスト）。
  `vizRegistry.js` に全 viz を登録し、Studio と同じ `type`（`<appId>.<appId>`）で
  そのまま使える＝**Studio ダッシュボードの定義をそのまま移植できる**
  - viz 側は2点だけ追加（`tools/` の生成スクリプトで機械適用）:
    `globalThis.__<NAME>_APP__ = App`（受け渡し口）と、
    `if (!globalThis.__DASH_PLATFORM_HOST__)` による自己マウント抑止
  - 各 viz に `src/host.jsx` を新設。**`export` を書けるのはこのファイルだけ**
    （`visualization.jsx` は esbuild エントリで、export を書くと成果物に `export{}` が出て
    Studio のパネルが真っ黒になる。既知の実害）
  - 対象外: `weather-panel`（`src/` が空でソース未実装）、`editor-probe`（検証用）

#### 修正

- **webpack の SVG ローダー衝突を解消**。`@splunk/webpack-configs` の base が
  svg を `asset/resource`＋`generator.filename` で処理しており、DPX 側で
  `asset/inline` を足すと ValidationError でビルドが落ちた。
  base 側の test から svg を外してから merge するようにした
- **空状態アイコンが黒い矩形で全面に伸びる問題を修正**（8 viz の CSS）。
  同梱 SVG が `viewBox` のみ・`fill="currentColor"` で、`<img src>` では
  サイズも色も効かないため、`width/height/opacity` を CSS で与えた
  （Studio 側の見た目も同時に改善される）

#### 検証

- 30 viz を1枚に並べた検証用ダッシュボード
  [`examples/all-viz-check.json`](examples/all-viz-check.json) を実機に push し、
  **全 viz が実データで作図されることをスクリーンショットで確認**
- ⚠ 検証サーチは **viz ごとに各 README のサンプル SPL** を使う。
  1本の汎用 SPL を流すと、多くの viz が「値列＝最終列」を既定にしているため
  最終列（`_time` など）を値と誤読して空になる。
  また `makeresults format=csv` は**フィールドがアルファベット順**で届くので
  **`| table` で列順を固定**する（これを怠り donut-graph / gauge-arc が空になった）
- ⚠ `dataContract` が空の viz（tab-selector 等）は**サーチを付けずオプションで設定**する
  （README の SPL は「トークンを受ける下流パネル」の例のため）

#### 配布物

### [0.1.0] - 2026-08-11

#### 追加（初回リリース）

プラットフォームの初回リリース。開発中に内部で刻んでいた 0.6.0〜0.12.2 の
イテレーション（`dist/` に残るアーカイブ）を本バージョンに集約した。

- **エンジン**: DPX スキーマ v1（CSS grid・パネル重ね置き・`style.z`）、
  タブ（上部/サイドバー・自動ローテーション）、トークン展開
  （SPL / earliest / latest / パネルタイトル。未解決トークンのパネルはサーチを実行しない）
- **データ**: 共有データソース（Studio 準拠・編集画面上部の管理メニュー）、
  パネル単位の `postSearch` 絞り込み、自動更新（秒指定）
- **入力**: dropdown / multiselect / text / number / timerange に加え、
  カレンダー（日付・期間）★Studio に無い。選択肢は静的リストと
  **サーチによる動的選択肢**の両対応
- **viz（14種）**: ネイティブ5（line / bar / value / status / table）、
  装飾2（text / clock）、図形5（rect / ellipse / line / glow / NOC フレーム）、
  試作 spike、既存 Studio 拡張 viz の互換アダプタ（world-map で実証）
- **見た目**: テーマプリセット9種・パネル質感11種（既定は NOC・角丸2px）・
  コーナーブラケット・背景エフェクト・入場アニメーション
- **編集**: インスペクタ（viz の editorConfig からフォーム自動生成）、
  Undo/Redo、Ctrl+D 複製、矢印キー微調整、Shift+矢印リサイズ、Ctrl+S 保存、
  SPL エディタは**編集終了まで実行を遅延**（blur / Ctrl+Enter で確定・Esc 取消）
- **表示**: 全画面表示（createPortal。transform 祖先下の fixed 崩れを回避）、
  キオスクモード、クリック→トークン（ドリルダウン）
- **起動画面**: 白フラッシュゼロ・react-page の3点ローダーより上に出す自前スプラッシュ
  （z-index 10001・システムフォントのみ）
- **ホーム**: DPX ダッシュボードのみを一覧（`version:1`＋`panels` 配列で判定。
  Studio の定義を誤って拾わない）
- **配布物**: `dist/dpx-0.1.0-248c467.spl`

#### 既知の制約

- 共有テンプレートが**カスタム Mako**（10.4.0 で非推奨・実行時の停止スイッチは現状 false）。
  代替は全数調査の結果すべて棄却済みで、意図して Mako を継続している
  （詳細: dpx-platform.md §1.1）。この構成のため **Splunk Cloud には持ち込めない**
  （AppInspect `check_for_custom_mako_templates` が 4.4.0 から failure になる）
- アプリ初回導入時のみ splunkd 再起動が必要（`appserver/templates/` の登録は起動時だけ）。
  以後の更新はインストール＋`_bump` で反映される
